## Must fix before launch

### M1. At D = 4,096 the latent prior falls below the wire codebook floor; a prior-only message out-ranks the receiver's own prior, and the arm's "no evidence" input differs between K0 and R >= 1 (the control's does not)

`train_3d_v431.py:310` `prior = LATENT_PRIOR / (n * D)` = 1e-4 / (8 x 4,096) = **3.05e-9**; `train_v378.py:130,135-136` quantise the wire precision on a log codebook over [1e-8, 128] with `safe.clamp(low, high)` and floor rounding. For p below `low` the clamp rounds UP: a prior-only factor (mask 0, `p_own = prior`) leaves the sender as `p_hat = 1.0e-8` = 3.28 x the receiver's own prior (measured; `v431_local_checks.py` section 2). The 2026-10-22 review-M1 invariant that the floor rounding was introduced for - "a prior-only factor can never out-rank the receiver's own prior under max-selection" (`train_v378.py:134`) - therefore no longer holds at this rung. At D = 256 / 1,024 it holds with margins 2.8 % / 1.6 % (p_hat 4.75e-8 vs prior 4.88e-8; 1.201e-8 vs 1.221e-8).

What it does and does not do (measured on an 8-agent chain, `train_3d_v431.rollout_max`, both layouts):
- The JOIN SEMANTICS are intact. Real evidence has q >= PRECISION_MIN = 1e-4 (`:99,192`), which the wire floors to 9.53e-5, i.e. >= 9,500 x the clamped prior; `select()` (`:301-305`) can never pick a prior-only message over own or remote evidence, and a coordinate with evidence anywhere gets the same mean and the same log-precision as in the control (toy: c1 own-only 1.1513, c2 remote-only 1.1573, c3 remote q = 4 -> -0.1713 at both D).
- What changes is only the coordinates with NO evidence anywhere in the forest: their mean channel is 0 in both cases, but the decoder's log-precision input (`:325`, `(1/P).log() / 8` at `:224`) is **2.4509 at K0 and 2.3026 at every R >= 1** in the arm (the incoming 1e-8 message wins the max over the own 3.05e-9), whereas in the control it is **2.2777 at K0 and at R8** alike (the own 1.221e-8 beats the floored 1.201e-8 message). So the arm's decoder sees a stage-dependent "unknown" level (0.148 apart, ~13 codebook steps), which the control's decoder never sees; the evidence band (<= 1.1513) stays far away from both, so the decoder can learn it, but it is a second difference between arm and control besides the layout, and it is undisclosed (D8-29 and the chain header lines 6-7 say "everything else is the control's").

Failure scenario: none of crash / hang; the risk is interpretive - a small K0-vs-R8 behavioural difference of the arm (e.g. a K0 / R8 gap that differs from the control's) could be read as a property of 4,096 coordinates when it is the floor clamp. And the documented wire invariant is silently broken by the batch that pushes D past 1,250 (the n = 8 threshold `1e-4 / (8 x 1e-8)`).

Fix (least invasive, keeps the control bit-for-bit): in `train_3d_v431.py:310` only,
`prior = max(LATENT_PRIOR / (n * D), 1e-8)   # v431: never below the wire codebook floor (train_v378 low), so a prior-only message cannot out-rank the own prior (review M1 2026-10-22)`.
For D <= 1,250 at n = 8 `max()` returns the identical float (control 1.2207e-8 unchanged - verified; test A's bit-for-bit assertion at 32x32x1 still holds). For the arm the own prior becomes 1e-8, K0 and R8 both read 2.3026, and the own factor wins the tie through the index term in `select()` (`:303`, measured: K0 == R8 after the clamp). The arm's K0 "unknown" input moves from 2.45 to 2.30, closer to the control's 2.28. Then: add to `test_3d_v431.py` B an 8-agent toy assertion that a no-evidence coordinate has equal log-precision at K0 and R8 for 64x64x1 (the three lines of `v431_local_checks.py` section 3 suffice), re-run the test on uk-linux CPU (35 s), copy, new sha at `chain_day6_3SZ.sh:34`, one clause in D8-29 and the header. If the owner prefers not to touch the trainer: amend D8-29, the chain header (lines 6-7) and the lease `expectation` (line 89) with the numbers above, so the K0 / R8 asymmetry of the arm is a disclosed confound rather than "the control's". Do NOT scale `LATENT_PRIOR` with D or assert `prior >= low` in the shared code path: the first changes the control's inputs, the second crashes the arm.
