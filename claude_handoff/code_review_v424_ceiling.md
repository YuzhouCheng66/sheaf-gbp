## Must fix before launch

**M1. The TRAIN codes are range-capped by the optimizer schedule, not by the data: after 8,000 steps every code has moved by at most sum(lr) = 0.42 in z, i.e. |mu| <= 0.41 and q in [1.6, 2.4]. The decoder is trained on these under-fit codes, so the ceiling is biased low.**
- Where: owned_ceiling_3d_v424.py:80-87 (one scene per step, `opt.zero_grad(set_to_none=True)`), :81-82 (one Adam over the decoder and all 384 code tensors; `CosineAnnealingLR(opt, args.steps, eta_min=args.lr*.05)` applies to the code group too), chain_day6_3SL.sh:60 (`--steps 8000`, default `--code-lr 2e-2`).
- Mechanism: with `set_to_none=True` only the visited scene's two code tensors carry a gradient, and Adam skips parameters whose grad is None. A scene is visited 8000/192 = 41.7 times, so each code tensor receives ~42 Adam steps, each of size <= lr(t) in z-space (Adam's normalised step), with lr(t) on the cosine from 2e-2 down to 5e-5 (I checked that the code group also ends at 5e-5). Sum over the visits = 0.42.
- Measured (CPU, synthetic maps, frozen random decoder, the real `source` / `rollout_max` / `stage_loss`): 8,000 steps / 42 visits: sum lr 0.421, max |z_mu| 0.432, max |mu| 0.407, z_q in [-0.40, 0.40]. 16,000 / 83 visits: max |mu| 0.71. 24,000 / 125 visits: max |mu| 0.86.
- So at TRAIN the mu channel uses ~105 of its 255 quantizer levels (6.7 of 8 bits) and the precision channel stays in a narrow band around its initial value; the decoder co-adapts to that band. At VAL the 300-step fit at 3e-2 can leave the band (sum lr = 9), but then it drives the frozen decoder into input ranges it never saw. Either way the number comes out low.
- This differs from the 2D protocol it mirrors. In owned_ceiling_v370.py:188-223 the per-scene tensor `codes[si]` is stepped whenever any of its ~24 items is in the 64-item batch (~600 of the 4,000 steps) with zero grads for the other rows; Adam then keeps moving every row on its momentum tail (~27 x lr per gradient event with beta1 = .9, beta2 = .999), so the 2D codes reached the clamp [-1, 1]. The 3D script has no tail: the movement is exactly sum(lr) over visits. The 2D runs confirm the codes were not the limit there: TRAIN K0 wall F1 .926 vs VAL .918 (16x16x1), .746 vs .694 (8x8x1), .643 vs .623 (4x4x4).
- Failure scenario: C1 comes out at K0 var .50 (above 3S-A's trained .436, below the .55 threshold) and the chain writes "8x8x4 256-D code CANNOT: representation limit", when the limit was the code learning rate x visit count. D8-6 then sends the project after layout / dimension instead of encoder / training.
- Fix (flags only, in the chain; no script change): `--code-lr 5e-2 --steps 16000 --time-cap 3000` for all four arms. Sum lr becomes ~2.1 in z (the full tanh range is reachable, q spans [0.4, 3.6]); each code gets ~83 updates. Time: a ceiling step is two decoder passes plus two rollouts; from 3S-A / 3S-W (0.12 / 0.22 s per 5-hop update) I estimate ~0.07 s (W1) and ~0.12 s (W2) per step, so 16,000 steps = ~19 min (W1) / ~32 min (W2), under a 3,000 s cap, and the arm stays well inside its 7,200 s lease (generation ~5-8 min, VAL fit 24 x 300 steps ~3-5 min). Alternative with a code change: give the code group a constant lr (LambdaLR with per-group lambdas) and keep 8,000 steps; then re-pin CSHA.
- Whatever is chosen, add the under-fit readouts of M2 (c) and (d); they are what tells an optimizer artifact from a representation limit.

**M2. The analysis has no validity gate, so an incomplete or under-fit arm is read as a verdict. Four cheap asserts / readouts are missing.**
- Where: chain_day6_3SL.sh:63-89 (analysis heredoc), :14-22 and :57 (expectation text), d8_67.md D8-7 lines 49-53.

## Checked, no issue
- **Faithfulness.** `source()` = `latent_quantize(tanh(z))` and `PRECISION_MIN + (MAX - MIN) sigmoid(z)`, identical to OwnedHead + SheafModel3D.source. `coverage()` = OwnedHead's `avg_pool3d((private >= 0), dims // (BX, BY, BZ)) > 0`, computed after :31 sets the layout. Join, wire, `stage_loss`, `predict`, `metrics3d`, `agg`, `stream_targets` are the trainer's own functions; `reached[0]` is the identity (hops 0) so the K0 target is the own map; `HOPS.index(8)` = 4. `T.CHART_M` is set per scene in the TRAIN loop (:87), in `score()` (:59, used by both the TRAIN sanity and VAL) and before the VAL fit (:117).
- **Union loss does not update codes.** CPU check: a backward through the R8 loss alone leaves `z_mu.grad` and `z_q.grad` None; the K0 loss gives gradients on exactly the masked coordinates (mask fraction .41 -> .406 nonzero), both for mu (through E/P) and q (through log 1/P); with `--union-code-grad` the gradient does pass the argmax `gather` and the wire STE to the codes. The default is off, as in 2D.
- **No VAL leakage.** The fit uses `tgt0` = own map and `mask` from the own map only; stage 0 reads no messages; the R8 features are composed after the fit under `no_grad` and scored against the never-fitted union targets. Decoder frozen (`requires_grad_(False)`, `eval()`; no dropout / BN so eval is a no-op).
