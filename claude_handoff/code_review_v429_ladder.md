### M3. The L1 arm changes the decoder as well as the code, in both directions; a non-lever L1 does not license "the code is not the limit"

`train_3d_v429.py:190` (`start = (min(max(16, BX), comp[0]), ...)`) gives L1 the schedule 32x32x8 -> 64x64x16 (one block) against the control's 16x16x8 -> 32x32x16 -> 64x64x16 (two blocks). Measured locally (CPU, `v429_local_checks.py`): L1 decoder 1,498,576 params vs 1,832,704; 6 Conv3d layers vs 8; the single block runs 96 channels at the full compute grid where the control runs 72 (so MORE full-resolution capacity); and the decoder's xy receptive field shrinks from ~37 compute cells (~7.4 m at 0.1 m voxels: 2 convs on the 16-grid + lift + 2 x 2 convs) to ~17 cells (~3.4 m). A room in HouseExpo is 3-5 m across: the control's decoder can integrate a whole room from sparse evidence, L1's cannot - a handicap; the extra full-res channels and the absence of any upsampling of the code are advantages. Any L1 outcome therefore has a decoder explanation in one direction or the other, and the pre-registered reading "neither lever => the code is not the limit at 16k updates" (header lines 22-23, D8-20) is not licensed by a non-lever L1. D8-20 does disclose the schedule difference and the parameter count, but not the receptive-field change, and the ladder text does not condition on it.

What I would do: fold the 32x32 code into channels and keep the control's schedule - space-to-depth in xy only: `fold = (max(1, BX // 16), max(1, BY // 16))`; `start = (min(16, comp[0]), min(16, comp[1]), min(8, comp[2]))` as in v428; `pre = Conv3d(2 * fold[0] * fold[1], c0, 3, padding=1)`; in `forward`, `grid.reshape(b, 2, BX//fx, fx, BY//fy, fy, BZ).permute(0, 1, 3, 5, 2, 4, 6).reshape(b, 2*fx*fy, BX//fx, BY//fy, BZ)` when `fx > 1 or fy > 1`. For BX, BY <= 16 the fold is (1, 1), the pre conv has the same shape and the same RNG draw, so test A (bit-for-bit vs v428) still holds; for 32x32x1 the decoder is the control's decoder plus 20,736 parameters in the first conv's input (1,853,440 total), identical depth, schedule and receptive field, and the information is preserved (the fold is lossless; trilinear downsampling to 16 would not be, which is what the current rule avoided). Cost: regenerate v429 (test B's `start == (32, 32, 8)` / `len(blocks) == 1` asserts become `(16, 16, 8)` / `2`), re-run `test_3d_v429.py` on uk-linux CPU, new sha in `chain_day6_3SD.sh:42`, D8-20 and the header lines 12-13 updated. If the owner keeps the disclosed design instead, amend D8-20 + header + the `ladder` strings in the analysis (lines 208-212) so that the L1 reading is "coordinates (with the one-stage decoder as a disclosed confound)" and a non-lever L1 yields "no evidence either way about coordinates; repeat with the folded decoder" rather than "the code is not the limit".

## Should fix or note

### S1. The 4+4 arm's precision codebook has 7 usable levels and collapses the whole upper range; disclose it and read L3 mainly at K0

`train_v378.py:130-136`: the Q-bit codebook is logarithmic over [1e-8, 128] with floor rounding. At Q = 4 (15 levels) the step is 1.662 nats = x5.27 per level; the learned range q in [1e-4, 4] (`train_3d_v429.py:95,179`) lands on 7 levels (4.07e-5, 2.15e-4, 1.13e-3, 5.96e-3, 3.14e-2, 0.166, 0.874) and EVERY q in [0.874, 4] goes to 0.874 (measured, `v429_local_checks.py`). At 8 bits the step is x1.096 (~115 levels in range); at 16 bits x1.00036. Consequences: (i) the max-precision join on the wire ranks remote sources by 7 levels and cannot separate any two sources with q >= 0.874; (ii) `rollout_max` compares the receiver's OWN factor unquantised (`p_own`, lines 296, 306) against incoming messages floored to the codebook (lines 302, 316) - by design (the 2026-10-22 review-M1 floor rule) - so at 4+4 an own q of 0.88 out-ranks every remote source, however complete, whereas at 8+8 the asymmetry band is < 9.6 %. K0 (no wire) is unaffected by the wire bits; R8 carries all of it. So L3's R8 result is "2x coordinates, 7 mean levels, AND a 7-level join key"; D8-20 discloses only "均值 7 级". If 3S-Q makes coverage precision the baseline (`PREC = coverage`), the effect is sharper still: q = 4 x coverage, so every block seen >= 22 % is one wire level and the completeness key 3S-Q is testing is destroyed on the L3 wire. Recommendation: add the codebook facts to D8-20 and the header; add to the analysis's `mech` for each arm the number of distinct wire precision levels in range and (from the final-val panel npz, where `q` is saved) the fraction of evidence coordinates with q > 0.874; state that the pre-registered "coordinates for bits at 512 B" question is read at K0 as the cleaner number and at R8 with the join-key caveat. Changing the codebook range to [PRECISION_MIN, PRECISION_MAX] would be the principled 4-bit design but is another variable and would need a v429-private copy of the wire (train_v378.py is pinned by running chains) - not for this batch.

### S6. Prior-only factors at D = 1,024 sit 22 % above the codebook floor

`train_3d_v429.py:294` `prior = 1e-4 / (n * D)` = 1.22e-8 at n = 8, D = 1,024 (4.88e-8 at D = 256); the codebook floor is 1e-8 (`train_v378.py:130`), so floor-rounding still keeps a prior-only message (1.0e-8 at 4 bits, 1.2e-8 at 8 bits) <= the receiver's own prior and the 2026-10-22 review-M1 guarantee holds. With n >= 10 agents at D = 1,024 the prior would drop below 1e-8, be clamped UP to the floor, and a prior-only remote factor would out-rank the receiver's own prior. N = 8 is fixed in this programme (`W.AGENTS`, run.json `agents: 8`); note it for any future N or D change.

### S7. The 32x32x1 trunk is effectively a per-column z-profile encoder
