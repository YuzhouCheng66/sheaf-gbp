## 2. 第一性原理：消息到底是什么，最少要多少

### 2.1 消息 = 发送侧的精确整数和【事实，断言】

- 消息公式：m_{s→r} = Q(f · (own_s + Σ_{k≠r} m_{k→s}))，f = w / (w + λ)，Q = 步长 1 取整。
- λ 是发送侧的足迹计数 k ≤ 7，h 是 z 的和，|h| ≤ k。所以 λ − λf = λ²/(w+λ) ≤ 49/1247 < 0.5，h 同理。取整把衰减整个抹掉：
  - **Λ 消息 = k_A = Σ_{a∈A} τ_a**；
  - **h 消息 = s_A = Σ_{a∈A} τ_a z_a**。
  - 这在 λ ≲ √(w/2) ≈ 25 台机器以内都成立。
- 推论：每台机器的信念 = 自己 + 全部入消息 = 全分量的 T = (K, S)。所以 summary 里机间信念差 rms = 0.0；本次 96/96 断言 `same_belief`。
- **这时 sheaf 耦合 w 实际上是无穷大，GBP = all-reduce(Σ)。** 二次能量、闭式解、两遍 GaBP 都还在，但它们算的就是一个整数求和。

### 2.2 每台机器必须拿到什么【事实】

- 解码器输入 = (x = S/K, log1p K, 高度)。在 K > 0 上，(x, log1p K) 与 (K, S) 一一对应。
- 所以"精度逐位不变"⇔ 每台机器都持有整份 T。
- 割集界：点对点链路上，每个比特只被一台机器收到；机器 a 收到的比特加上自己的数据 X_a 必须决定 T。所以
  **全网字节 ≥ Σ_a H(T | X_a)**。这对任何协议都成立，交互式也一样。
- 推论：树上的收集—分发不是冗余的来源。冗余来自"n 台机器各要一份 T"。

### 2.3 实测：T 有多贵，自己的数据能解释多少【探针】

- **T 只发一次**（K 先、D 后；静态表留一房出；每房中位）：
  - 342101：K 9.07–9.20 KB + D 12.56–12.68 KB = 21.6–21.9 KB；
  - 342202：K 9.07–9.20 KB + D 9.54–9.72 KB = 18.6–18.9 KB。
- **8 张自图之和**：26.5–33.0 KB（O7）。同一编码器（K1 + D1）下，T / Σ 自图 = 0.70（96 个的均值）。
  - 原因：足迹边界与 z 的分歧是各机私有的，求和合并不掉。
- **按发送侧大小 m 看消息字节**（种子 1，按 m 求均值）：
  - 用新编码，m = 7 时 25.6 / 22.0 KB；
  - 7 张单机消息之和是 33.4 / 28.4 KB，比值 0.77–0.78；
  - 字节与 m 近乎线性，约 3.1–3.6 KB / 机。
- **割集下限 Σ_a cost(T − own_a | own_a)**，每房中位：

## 4. 逐项回答

### 4.1 (a) 足迹计数 k

- **三维上下文**【探针】。
  - 用 (k[z−1], k[y−1], k[x−1]) 的值作上下文：k 通道 89–90 → 76–77 KB（−14 %）。
  - 富上下文 + 静态表：T 的 K 从 10.3 → 9.1 KB（−12 %）。
  - 再加更多邻居就变差（KC 9.5 KB）：数据量不够撑更多上下文，已经饱和。
- **射线几何**【事实 + 估计】：没有用。
  1. 接收方要的是**和** Σ_a τ_a，不是单个足迹。和比部分便宜：T 的 K 9.1 KB < 8 机各自足迹之和约 13–15 KB。按单机足迹分发只会更贵。
  2. 用位姿 + 深度重建单机足迹，要发深度 / 残差。R-B §3 已测：噪声世界 5.6 % 已知体素违反光线结构，残差 4.1 KB / 机，比 ctx 掩码贵 3 倍。
- **跨跳相关（子树计数 = 孩子计数之和）**【事实】：只有接收方手里有子消息时才用得上。
  - 树 GBP 里，唯一同时持有两条相关消息的是**同一条边的两端**（反向消息）。这已经用上了（P2）：只省 1–3 %。
  - 原因：下行消息是"另一侧的私有边界之和"，与接收侧的边界几乎无关。
  - q 收到的 m_{p→q} 里含 m_{c→p}，但 q 没有 m_{c→p}。
- **条件于接收方已知**【探针】（全网字节，K 与 D 一起）：
  - 只条件于接收方自己的足迹与 z：−3.4 %（342101）/ −4.2 %（342202）；
  - 条件于"当时的部分信念"：−3.2 % / −3.9 %。
  - 上行消息的这种侧信息只在解码端，按 Slepian–Wolf 要块码（LDPC 伴随式）和已知联合分布，还有小概率解码错误。为 3 % 不值，奥卡姆否决。
- **结论**：k 的无损下限约是每份 T 9 KB × 0.93 × 8 ≈ 68 KB ≈ **0.09 倍**。

### 4.2 (b) z 通道

- **条件于 k**【探针】：改发 d = k − s ∈ [0, 2k]，上下文含 k 本身。
  - 字母表随 k 变，s = k（全 +1）是最常见的情形，d = 0。
  - 比 O7 的 s 通道省 26 %：155 → 115 KB（342101），118 → 86 KB（342202）。
  - **这是单项最大的无损收益。**
- **三维上下文**：已含 d[z−1]、d[y−1]（类 0 / 1 / 2 / 3+ / 无）；更富的上下文 + 静态表再省 1–2 %。
- **条件于接收方信念**：1–3 %，理由同 k。
- **两个检查点差 25 %**：D 每份 T 是 12.6 vs 9.5 KB，而 z 熵只差 0.76 vs 0.74 bit。D 的代价由机间分歧与空间结构决定，不由单机熵决定，所以码率项要直接作用在消息上（§5）。
- **只报告：矩形式**。如果解码器不吃 log1p K，只吃 (x, 已知)，下行可改发 (掩码, x)。T' = 16.7–21.2 KB，只比 T 省 5–10 %。
  - 原因：x = (K−D)/K 本身就带着 K。K 的内部值不是可单独剥掉的冗余。
  - 这还要改解码器、重训（GPU），不值。

### 4.3 (c) 协议层：只发"全体"再让各节点减去自己侧

- **精确性**【事实】：设父 p 的信念 b_p = own_p + Σ_k m_{k→p}（全是整数）。则
  m_{p→c} = Q( f · (b_p − m_{c→p}) )，f = w / (w + (Λ_b,p − Λ_{c→p}))。
  - 孩子知道 m_{c→p}（自己发的）和 w，所以收到 b_p 就能逐位算出 m_{p→c}。
  - 这对任意 w 成立，不只是 E3-L3 的大 w 区。
  - 它是 GBP 的"除法 / 减法"形式（Hugin 式更新），消息逐位相同，信念逐位相同，仍是同一能量上的精确 GBP。合 C3（固定整数求和）与 C5（每个节点持有自己的信念，读出不进消息）。
  - E3-L3 区里 b_p = T，所以"发全体"= 父把同一个 T 发给每个孩子。
- **字节**【事实 + 探针】：给定 m_{c→p}，b_p 与 m_{p→c} 一一对应，所以 H(b_p | m_{c→p}) = H(m_{p→c} | m_{c→p})。
  - 发全体与发差的信息量相同，省下的只是"条件于反向消息"那约 2 %（P2，已含在 W 里）。
  - 实测直接编"T | 反向消息"反而贵 13 %（字母表更大），所以线路上仍发差。
- **"只发一次"**：需要一次发送被多台机器同时收到（广播 / 组播）。
  - 下行就只剩 T 一份（约 0.024–0.029 倍），加上行 0.050–0.064 倍，合计约 0.075–0.095 倍。
  - 但 O7 与对照的判决口径都是"每条有向消息计一次"。对照在广播口径下也会降（它的下行同样是"全体 − 本侧"）。不能用来过 0.15 倍线，只能作为将来改口径时的参照。
- **违反 C5 的"下行发读出"**：所有机器信念相同，读出也相同，所以根节点解码一次、下发三态读出，R8 输出逐位相同。0.082–0.098 倍。
  - 按 R-C 的 C5 判定，它只能作只报告行。
  - 它的价值是说明：下行那 75 % 的字节，是在给每台机器送一份"解码之前的"共识场。

  1. n 台机器各下载一份 T（下行 ≈ 75–78 %，割集界不可删）；
  2. T 里 D（z 的机间分歧，51–58 %）；
  3. T 里 K（足迹边界，42–49 %，被 C2 与"Λ = 足迹"锁死）；
  4. 上行的中继重数（约 25 %）；
  5. 编码器本身的低效（O7 比下限多约 50 %，W 消掉其中约 2/3）。

### 5.2 训练时加码率项（学到的熵模型兼作先验）【估计】

- **需要多少**：0.15 倍 ≈ 113–115 KB / 房。
  - 实用编码约在下限之上 8–13 %，所以下限要 ≤ 100–106 KB。
  - K 部分下限约 68 KB 不动，所以 D 部分要 ≤ 32–38 KB，即每份 T 的 D ≤ 4.3–5.1 KB。
  - 现在是 9.5（342202）/ 12.6（342101）KB，**要压 2–3 倍**。
  - 即使 D 降到 0，也只到约 0.10 倍：K 是硬地板。
- **能到哪**：
  - 两个检查点在同精度下 D 已差 25 %，说明有自由度。
  - 码率项若直接作用在消息上，例如 λ · Σ_e R(d_e | k_e) 或单机代理 (n−1) · R(z_a | τ_a, 上下文)，D 压 1.5–2.5 倍是合理区间。
  - 合计约 **0.14–0.18 倍**，P(≤ 0.15 倍且 4 格家具 ≥ −1 pp) ≈ 0.3。
- **代价**：
  1. 一个 GPU 租约（两个种子约 2 × 6,000 s）；
  2. E3-L 的旧病：码率对偶步振荡、支撑塌缩（D8-57）；
  3. 降低 D 的本质是让各机的 z 一致，也就是源端去噪。机间错位下这正是 QPOST4 在 cam 档付 3 pp 的地方（D8-56），cam 档有风险；
  4. 多一个熵模型，模型不再"一个隐码 + 一个能量"那么干净。

**我的意见**：先做 §6 的 CPU 批，把"无损到不了 0.15 倍、下限 0.18–0.21 倍"正式入档。然后由用户二选一：

- 承认 n · H(T) 地板，把字节线按它重定（例如 ≤ 0.25 倍）；
- 或者花一个 GPU 租约做码率项。

不建议在无损路线上继续加更复杂的熵模型：下限已在 0.18 倍以上，收益上限约 10 %。

## 6. 下一批预注册草案：E3-L3-W"线路编码器替换"（纯 CPU，0 GPU）

- **单变量**：线路编码 O7 → W。其余全部冻结：
  - 两个 E3-L3 检查点（sha 1fa0cb39… / 3d332d40…）、阈值、`L.gabp(…, 'round')`、消息本身、解码器、读出。
- **W 的定义**（写死，与本审查 `rh_codes.py` 的 P2 和 `rh_agg2` 的择优相同）：
  - 每条有向消息 (k, s)：
    - 先编 k：全网格，C 次序，上下文 = (k[z−1], k[y−1], k[x−1]) 截到 0..m，字母表 m+1，m = 发送侧机数；
    - 再编 d = k − s：只在 k > 0 上，上下文 = (k, d[z−1] 类, d[y−1] 类)，类 = 0 / 1 / 2 / 3+ / 无；字母表 2k+1。
  - 每条边上**后发**的那条消息（发送侧较大，L.gabp 的次序），两个上下文再乘反向消息同体素的 (min(k', 4), d' 类)。
  - KT α = 1/2 自适应，每条消息重置。
  - 每条消息 1 bit 选 W 或 O7（取短者）。
  - 头 4 B。
- **实现**：
  - 纯 Python 32 位区间编码器。计数用 2× 整数，使 α = 1/2 精确。
  - 编码端上下文向量化预算；解码端逐体素顺序解。
  - 估计约 1.8×10⁹ 个符号（编 + 解），8 进程约 30–60 分钟。
  - 不装新包；constriction 等需要用户批准才装。
- **对照**：E3-L3 的 O7 字节。逐房重算，四格中位必须与 summary.json 的 `bytes_median` 差 ≤ 0.01 B，否则 INCOMPLETE。
- **范围**：VAL cam_nf，24 房 × 噪声种子 1、2 × 两个检查点 = 4 格。fresh 只报告。不碰 TEST。
- **判据**：
  - **W-LEVER** 要同时满足：
    - 4 格每格"每房 W / O7"的中位 ≤ 0.85，且每格 ≥ 22 / 24 房 W / O7 ≤ 0.95；
    - **无损往返**：全部有向消息 decode(encode(m)) 与 m 逐位相同；
    - 解码后各机信念 (Λ_b, h_b) 与 GaBP 输出逐位相同（断言）。由此精度逐位不变，不重新计分；
    - 实际码流 ≤ 理想码长 + 8 B / 消息（报告超出量）。
  - **NOT**：任一格中位 > 0.85。
  - **INCOMPLETE**：任一往返失败、O7 对账不符、缺房 / 缺消息、检查点 sha 不符。
- **只报告**：
  - 相对对照的倍数（按 D8-63 的 0.15 倍线读）、上行 / 下行拆分；
  - 割集下限（`rh_tctx.py` 的 floor KB + DB）；
  - 静态表变体（表在 fresh 上拟合、用于 VAL，反之亦然）；
  - fresh 面板；违反 C5 的读出下行。
- **预测**：
  - W / O7 每格中位 0.76（0.74–0.79）；
  - 相对对照 342202 约 0.21、342101 约 0.25；
  - P(W-LEVER) = 0.9；P(相对对照 ≤ 0.15 倍) < 0.05；fresh 同向。
- **后果**：
  - W-LEVER：E3-L3 的线路改记 W，字节 0.21–0.25 倍入档；同时"无损路线下限 0.18–0.21 倍"入档，结束"只换熵编码到 0.15 倍"这条路。
  - 之后由用户决定：重定字节线，或做码率项（GPU，单变量 = 损失加 λ · R）。
