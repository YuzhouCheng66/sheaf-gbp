## 0. 结论

1. **cam 档 B4 的 602 KB 里，约八成是 log-odds 幅值。这些幅值对求和融合没有用。** 改成每机每体素一票（±1），家具平均只低 0.3–1.1 pp，空闲召回反而高 0.5–1.3 pp。只这一步，中继字节就降到 1/4。
2. **收集—分发协议的下行只发总和的三态，每房约 85 KB（≈ 7 倍于 B4）。** 这一步不用学习，精度与 B4 相当。
3. **完美去噪的下限就是 S0：6.1 KB/房。** 现实可达估计 15–35 KB【推测】，相对 B1 是 29–68 倍。
4. **E2 不应先做。** 噪声档三态比特里 54 % 是噪声，学习先验在噪声流上我预测只能做到 0.88–0.97 倍，过不了 0.85。
5. **"四个一"仍然成立，要改两处：**
   - 状态从"整数 log-odds"改成"整数票数"。
   - 位姿 stalk 在噪声档从可选改为必备。

- **三态的噪声增量 1.7 KB** 拆成两块：

  - 占据噪声 +0.91 KB。每机约 1,200 个干净空闲处的伪占据、1,000 个干净未知处的占据、430 个漏检。

**全网字节**【E1，VAL 种子 1，中位数相减，只是近似拆分】

| 档 | 字节 | 说明 |

**结论**：
- **99 倍里只有一部分是"不可压的噪声"**，相当一部分是编码器没利用光线投射。

## 3. E2、E3 各能贡献多少，以及倍数预测

- **E2**：噪声档三态比特中 (0.62 + 0.91) / 2.82 = 54 % 是噪声，学习先验只能压剩下的结构部分。
  - 噪声流上预测 0.88–0.97 倍；
  - 干净 S0 流上 0.85–0.92 倍（文献：稀疏点云 4–10 %）。
  - 按 D8-38 的 0.85 判据，大概率不是杠杆。
- **E3（去噪）**：同时动精度和字节，噪声比特只有它能删。若删掉 50–90 % 的三态噪声比特，ctx 线路约 40–60 KB，结构码线路约 15–35 KB【推测】。

## 4. 奥卡姆："四个一"在噪声档

| 部件 | 裁决 | 依据 |

| 整数 log-odds 状态 | **改为整数票数**，计数就是状态 | 见 §2。干净档时各票不冲突，票和的符号就是并集，±∞ 的特例因此可以删掉。积分器只留在每机内部 |

## 5. 压缩上下一步最值得做的一件事

**做 0 个租约的 CPU 批次"噪声档诚实线路"。**

**做法**（森林、求和、计分全部沿用 E1）：
- 状态用一票 ±1。
- 每机证据 = 盒子码（沿用 E0 的 W3 编码器）编码的 τ = 0 占据集，在 cc 族的 m = 4 删除（删掉小于 4 体素的连通块）之后编码，外加 float32 相信位姿。接收方做光线投射，得到已知 / 空闲。
- 收集—分发：上行发本侧各机码，下行发总和的盒子码。
- 与 B4、B5、§2 的一票 ctx 在 VAL 与 fresh、两种子上对比。
