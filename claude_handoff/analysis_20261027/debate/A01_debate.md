# A01 辩论稿：码率视角

A01，2026-10-27。读了 A02–A10 全部 9 份。新探针 `probes/A01/probe_debate.py`：本机 CPU，单进程，6 房 × 8 个智能体。

## 0. 先说共识

十份稿里有九份**独立**测到同一件事：自己的地图 = 光线投射（观测占据 O, 位姿），逐体素 0 误差。A02、A03、A05、A06、A07、A08、A10 各自复现了这一点。由此，**不学习的精确编解码器在 F1 和字节两个轴上同时支配现模型**。

还剩三处分歧：
1. 最强无损到底多少字节；
2. 学习还剩什么价值；
3. 现有评估还能不能区分方法。

## 1. 全场最强的 3 个设计（都不是我的）

**① A03 设计 A RAY-SHEAF：平面图 + 实心盒 + 位姿，光线投射解码。** A06 ProgSheaf 和 A08 D1 属于同族。

- **为什么强：**
  - 唯一在 **24 房**上实测的设计：自己的地图 198 B，收敛消息 317 B，R8 并集 561 B。
  - 浮点位姿下 192/192 逐体素精确；不用标签时 190/192。
  - 自己找了反例：旋转 45°（P5）、测距噪声（P6）。
- **最薄弱的假设：**轴对齐实心盒 + 无噪声。
  - 旋转 45° 时 245 → 394 B。
  - σ = 2 cm 噪声时，无损外壳 798 → 3,882 B。
  - 学习 AR 先验的 130–160 B 没有测。
- **我的加强：**
  - 盒子解释不了的部分，改用我的光线序残差。它是通用码，不假设盒子，6 房上是 250 B。编码端逐条消息取两者中较小的，代价 1 bit 标志。这样在旋转和曲面下会平滑退化，而不是爆炸。
  - 位姿按 float32 记 26 B（A02、A10 实测逐位精确）。用 44 bit 位姿只能到 .998。
  - 线路用 delta，并以反向消息为条件（A02 的腔条件 0.76×），按"每边整场"报字节。

**② A02 G1 GenFact：事实格 + 无模态补全 + 腔条件。**

- **为什么强：**
  - 测出了两个新的量：无模态补全让可见部分便宜 35 % / 43 %；腔条件让边消息降到 0.76×。
  - 推导并实测了"采样伤 F1"：家具 −6 到 −14 pp，F1 最优判决是 θ\* = F\*/2。
- **最薄弱的假设：**编码顺序。同样是精确码，不含位姿时栅格序是 265 B，我的光线序是 250 B，A03 的盒子约 192 B（三者面板不同，见 §5 E0）。"next-scale 深度先验再省 30 %"也没有测。
- **我的加强：**
  - 这三者是同一个原理的三种实现："未知区是 don't-care"：
    - 光线序：根本不访问未知区，零成本；
    - 盒子：结构化的补全；
    - 无模态贪心：在栅格序里补全。
  - 应该在同一批房子上做一次决赛（见 §5 E0），而不是各自报数。

**③ A07 D2：噪声世界 + 按真值评分 + 树上 log-odds 求和。**

- **为什么强：**它是唯一回答了"学习还剩什么"的设计。
  - cam 噪声下，无损三态码膨胀 1.8 倍（2,472 B）。即使把噪声图无损送达，按真值打分家具也只有 .775（K0）/ .756（R8）。
  - 树上求和比 max 高 8–18 pp。
  - 机间坐标误差单独就让并集家具掉 16–29 pp。这只有带位姿 stalk 的 sheaf 融合能救。
- **最薄弱的假设：**
  - 噪声参数没有标定，只有 6 房、单种子；
  - "学习先验能把家具去噪到比地板高 5 pp"没有测；
  - 需要用户同意改目标。
- **我的加强：**
  - 编码器设计成"先 MAP 去噪，再用精确结构码编码去噪后的世界"。去噪后的世界应该接近干净世界的 ~200–260 B，所以相对无损噪声图约 10 倍，相对 gzip（约 4,570 B）约 18 倍。这样"几十倍"第一次能诚实地说出来。
  - 指标加上空闲召回（见攻击 1）。

## 2. 我要攻击的 3 个论断

**攻击 1：评估漏洞。所有"F1 = 1"的主张都受影响。**

四个 F1 只统计"目标已知区内判为占据"的体素，FPR 只罚"未知判成已知"。所以只要"S 处判占据、其余全判未知"，就能拿满分。

`probe_debate` 实测（K0 / R8）：

| 输出 | 表面 / 可变 / 家具 F1 | FPR | 空闲召回 | 三态准确率 |
|---|---|---|---|---|
| S-only | 1.000 / 1.000 / 1.000 | 0 | **0** | .13 / .15 |
| 现模型 | — | — | .970 / .977 | — |

推论：
- 不传位姿、不做投射，ctx(S) = 418–544 B 在现有指标下就已经"无损"。"可见性免费"有两层原因：一是能推出来，二是根本不计分。A09 先指出了这一点，这里给出数量。
- 删掉 known 头的学习设计（A03-B、A04-PV、A05-RAYFIELD、A09-W）都可能靠"多报未知"白捡 F1。
- **修正：**主表加空闲召回，保护线为 ≥ 对照 − 1 pp。精确投射码的空闲召回 = 1，不受影响。

**攻击 2：拿 GPU 租约去打磨一个已被支配的表示。**

| 设计 | 实验 | 预注册中"成功"的结果 |
|---|---|---|
| A09 | A1：3S-Z2 + 率项，2 个租约 | K0 450–700 B，R8 −0.3 pp（家具约 .6–.7） |
| A04 | 实验 1：4 通道 payload | 家具 +5 pp，@ 2,048 B |
| A05 | E1：结构层给解码器 | 家具 +6 pp，@ 2 KB |
| A03 | B：RK-Δ | 家具 .62–.68 |

- 已测的精确码约 220–276 B（位姿统一按 26 B 计），家具 1.000。
- 所以上面四个即使全部"成立"，仍然是字节多 2–9 倍、家具低 30–40 pp。
- 问题在对照：它们的对照是旧的学习 run，判据最多只能说"比旧的好"。下一代决策要的对照是精确码的率失真点。
- 结论：这类实验不该占租约。首击损失、射线终止损失这些部件值得做，但应该直接放到噪声面板上做。

**攻击 3：对学习潜码做高斯信息相加，会重复计数。**

- 针对的论断：
  - A09 设计 B："信息相加的高斯 GBP，森林上精确"；
  - A08 D3："估的是同一个变量，所以高斯相乘有原理可依"。
- 森林上精确的前提是：给定潜变量，各因子条件独立。但这里的"证据"是重叠观测的确定性编码，不是独立测量。
- 实测（`probe_debate`，R8 并集）：

  | 单元 | 平均观测次数 | ≥ 2 个智能体看见的比例 |
  |---|---|---|
  | 已知体素 | 2.87 | 75 % |
  | 32×32 竖柱 | 3.25 | 81 % |
  | 64×64 竖柱 | 3.13 | 79 % |

- 信息相加会把这些格的精度**虚高约 3 倍**，均值则被不同部分视角平均成模糊（A09 自己也承认有"纠缠"）。
- "发似然消息（后验减先验）"只防住了先验的重复计数，防不住证据的重复计数。
- 合法的做法：确定性证据用幂等 join（max、OR、区间交）；只有条件独立的传感器噪声（A07 D2 的逐射线 log-odds）才相加。

## 3. 合成提案：RAY-PROG Sheaf

这里把四份稿的部件拼起来：A03/A06/A08 的精确程序码、A01 的光线序残差与线路、A02 的腔条件、A07 的噪声评估。

**stalk 索引集与内容。**

| 索引 | 范围 | 干净世界 | 噪声世界 |
|---|---|---|---|
| I_pose | 8 个智能体 | float32 3 个位姿（26 B）；集合并 | SE(2) 高斯 |
| I_glob | 全局 | 墙高、门高；平格 | 同左 |
| I_plan | 128² 竖柱 | {⊥, 墙, 门楣}；OR | 同左 |
| I_vox | 128²×32 体素（信念层） | 三态格 {⊥ < 空，⊥ < 占}，即 `stream_targets` 的 max | 量化 log-odds ℓ ∈ {−15…15}，精度为 \|ℓ\|（A07 D2） |

线路语言 = 程序（平面图 + 一致集 [O, ¬F] 里的实心盒）+ 光线序残差事件。编码端逐条消息取较短的一种。

**GBP 与能量。**
- 干净世界：
  - 消息与信念：m_{u→v}^{t+1} = x_u ∨ ⋁_{w≠v} m_{w→u}^t。
  - 能量：E(t) = Σ_v Σ_x [h(x\*) − h(b_v^t(x))] + Σ_v |A\* ∖ A_v^t|，即 Tarski 流，单调不增，直径轮后为 0。
  - 线路无损，所以编码前后的轨迹逐位相同。
- 噪声世界：
  - 体素层在 Kruskal 森林上对 log-odds 整数求和。对条件独立的噪声这是精确的；能量是 Bethe 能量。量化向零取整。
  - 位姿 stalk 用带 SE(2) 限制映射的高斯 sheaf Laplacian，做块坐标 GBP（A07 D3），能量不增。这是全系统唯一真正需要"非恒等限制映射"的地方，也是 sheaf 相对"无损体素传输"的结构性优势。

**线路与熵编码。**
- 每轮每条有向边只发接收方没有的内容：delta、支配剪枝（A04 L-Δ、我的 0 违例断言），并以反向消息为条件（A02 0.76×、A08 −25–29 %）。
- 调度用收集—分发（A10）。
- 先验分三部分：盒子 / 平面的 AR token 先验（A03 A-1），光线序事件上下文模型（A01，约 0.1 M 参数），两者都以接收方状态为条件。

**解码器。**栅格化 + 光线投射，结果精确。噪声世界里先做 MAP 去噪，再按区域取 F\*/2 判决（A02、A06）。

**损失。**干净世界只有比特 NLL。噪声世界是 R + λ·D_GT（D_GT 按干净真值在观测区上计，家具区加权），并加空闲召回保护。

**训练阶段。**

| 阶段 | 资源 | 内容 |
|---|---|---|
| S0 | CPU | 精确码 + 计数先验，见 §5 E0 |
| S1 | 1 个租约 | 学习先验 |
| S2 | CPU | 生成噪声面板，需用户批准 |
| S3 | 2 个租约 | 噪声面板上的去噪编码器 |
| S4 | — | 位姿 GBP 配准 |

**预计（干净世界）。** 字节依次为自己的地图 / 一条有向边整场 / R8 并集 / 每房网络。

| 阶段 | 字节 | 来源 |
|---|---|---|
| S0 | ≈ 220 B / 300–450 B / 600–750 B / 5–9 KB | 由已测部件拼成：A03 198 B 换成 26 B 位姿；本人边会话 590 B；A10 8.9 KB/房 |
| S1 | 150–190 B / 250–350 B / 450–600 B / 3.5–6 KB | 估计 |

- 以 S1 自己的地图取中值 170 B 计，相对各基线的倍数：

  | 基线 | 倍数 |
  |---|---|
  | 诚实最强无损（即 S0 本身，约 220 B） | 1.3× |
  | ctx | 8.1× |
  | gzip | 16× |
  | 原始栅格 | 770× |
  | 现系统（每房网络 229 KB） | 约 45× |

- R8 表面、K0、家具区 F1 全部 = 1.000，空闲召回 = 1。

**预计（cam 噪声面板，估计值，作为目标）。**
- 自己的地图 250–400 B：相对无损噪声 ctx 6–10 倍，相对 gzip 11–18 倍。
- 按真值评分的家具：K0 .80–.85；R8 .85–.90（有位姿 GBP 时）。地板是 .775 / .756，现行 max 规则是 .627。

**学习在这个合成世界里还剩什么价值？**
- 只剩码率，而且有界：
  - 光线序计数先验比自适应码省 41 %（424 → 250 B）；
  - A02 的静态先验省 17.5 %，A03 P7 的联合表省 19 %；
  - 现模型当超先验再省 24 %；
  - 离 DL 最多还有约 2 倍。
- F1 已经被精确码封顶。所以在干净世界里，"学习 + sheaf-GBP"证明不了 F1 上的价值。

**评估必须改：**
1. 加入噪声，并按干净真值评分（A07 D2）；
2. 加入空闲召回（攻击 1）；
3. 加入旋转家具、非曼哈顿墙和留出类别的面板，检测生成器泄漏（A03 P5、A07 p4）；
4. 加入机间坐标误差，让配准成为 sheaf 的独有价值；
5. 码率主指标改为每房网络字节，并报对精确码凸包的 BD-rate；
6. 保留干净世界，作为精确码的回归锚点。

## 4. 修正我自己的设计

1. **撤回"Ⅰ 光线序码是最强无损"。** A03 的盒子码在 24 房上是 198 B，比我在 6 房上的 250 B 少约 20 %。改为两者取其小，光线序码降为通用残差。
2. **位姿从 13 B 改为 26 B。** 13 B 是我外推的；A02、A10 实测 float32 才逐位精确。我所有的字节数相应加 13 B，Ⅰ 的自己的地图变成 276 B。
3. **Ⅱ 的超先验从高斯潜码改为结构程序（干净世界）。** 高斯潜码只留给噪声世界的去噪编码器。我的 −24 % 是"潜码当超先验"的存在性证据，不是方案。
4. **Ⅲ 并入合成提案。** A03、A06、A08 已经在 CPU 上做完了我提议的神谕实验（精确，约 200–280 B）。DL 级的"词"码（A08 D2 的 85 B）降级为"知道生成器的上界"，单列报告。
5. **所有报告加空闲召回列。**
6. **保留的结论：**
   - 会话口径：我测的每边整场 884 B，乘 14 条有向边约 12.4 KB/房（13.6 bit/stalk；按 7 bit 计是 6.9 KB/房），与 A04 的 5.7、A07 的 8.7、A10 的 8.9 KB/房同量级；

**我的前 3 名：**
1. A03 RAY-SHEAF（与 A06-1、A08-D1 同族）；

合成提案就是把这三者拼起来。

**第一步实验 E0：精确编解码器决赛，纯 CPU，不占租约。**
- **单变量**：线路表示，臂之间其他一切相同，全部用光线投射解码。
  - 臂：ELS 栅格 KT（A07）、光线序（A01）、平面 + 盒 + 残差（A03 / A06），每臂各做"有 / 无腔条件"两个版本。
  - 对照：3S-X 校准规则 + 熵编码 + delta。
- **数据**：VAL-24 与 fresh-24，按种子重建浮点位姿（A03 已在本机重建过 VAL-24）。
- **"两种子"**：先验分别在两个互不相交的 TRAIN 半集上拟合，每个半集 ≥ 100 套房子。
- **实现**：真实区间编码器往返；全部 192 个智能体 × 5 个 hop 都做逐体素断言。
- **预注册判据**：
  - (a) 两个面板 100 % 逐位精确；
  - (b) 最好的一臂在两个面板、两个半集上都满足：自己的地图中位 ≤ 250 B（含 26 B 位姿），边会话中位 ≤ 450 B，每房网络 ≤ 8 KB；
  - (c) 所有精确臂在 F1、空闲召回、字节三项上都支配对照。
