# A09 辩论稿：训练、数据与算力现实派

读完 A01–A08、A10。新增一个 CPU 探针 `probes/A09/p6_network_like_for_like.py`（只读已有 JSON，单进程，内存 < 100 MB）。没用 GPU，没碰 uk-linux，没改别人的文件。

**立场一句话**：十个视角独立得到同一条物理事实——自己的地图 = 光线投射(相容世界, 位姿)。所以在无噪声世界里，"学一个有损体素码"的每个 GPU 租约都花在一个已被 CPU 编解码器支配的点上。GPU 应该只花在两处：(1) 精确码流的**概率模型**；(2) 一个**会让学习有用的新评估世界**（噪声、坐标误差、旋转、留出家具，按真值评分）。

## 1. 全场最强的 3 个设计（不含我的）

**① A03-A RAY-SHEAF（平面图 + 实心盒子 + 光线投射）。**
- 为什么强：唯一在 24 个 VAL 房子上实测的精确结构码，且分割不用标签。浮点位姿下 190/192 逐体素精确，另外 2 张 ≥ .9995。自己的地图 198 B，收敛消息 317 B，R8 561 B。A03 还自己做了扰动：旋转 45° 字节 ×1.6，2 cm 测距噪声下无损外壳 ×4.9——是全场最诚实的设计。
- 最薄弱的假设：轴对齐盒子，加上精确共享的位姿与传感器模型。
- 我的加强：
  - 熵模型的训练数据要 TRAIN 的浮点位姿，缓存里没有。按种子重算约 30–45 分钟 uk-linux CPU，要排在 A-1 之前。
  - 贪心覆盖 0.2–0.3 s/图，37,664 张 TRAIN 图约 2–3 核时，可以接受。
  - R8 精确解码每个"智能体 × hop"要投射约 24 个位姿：numpy 约 30 s，VAL-24 全部 hop 在 14 核上约 25 分钟。GPU 版要用整数 DDA（采纳 A07 的建议）才能跨设备逐位一致。
  - 第一判据面板用 fresh-24，同时在 A07 的旋转和噪声面板上报码率。

**② A02-G1 GenFact（事实格 + 世界生成先验 + 渲染）。**
- 为什么强：把"压缩再生成"讲成了精确的事。
  - 生成模型只进熵模型，再加遮挡区的贪心无模态补全（−35 % / −43 %）。
  - 采样伤 F1 的推导（期望误差最多 2 倍，F1 最优判决阈值 F*/2）与实测一致（−6 到 −14 pp）。
  - 静态先验实测 K0 291 B、腔条件边消息 460 B。
- 最薄弱的假设：深度 next-scale 先验比计数模型强 ≥ 20 %。A07 实测留一计数上下文只省 5 %，A10 省 13–19 %，增益很可能偏小。
- 我的加强：
  - 按项目实测的时间模型（有效约 58 TFLOPS），9.5 TFLOP/步约 0.16 s，不是 0.1 s；一个租约约 4 万步，够用。
  - 两个种子用两个不相交的 TRAIN 半集拟合，这一做法要写进所有先验实验。
  - 概率必须整数化，并在 CPU 和 GPU 上做编解码往返，否则"无损"不成立。

**③ A07-D2（噪声世界 + 按真值评分 + 先验去噪证据格）。**
- 为什么强：它是唯一让"学习"和"相对无损几十倍"重新变得有意义的设计。
  - cam 噪声下无损代价变为 ×1.8（K0）/ ×2.4（R8），而无损送达后按真值评分只有 K0 表面 .918、家具 .775。
  - 机间坐标误差 5 cm / 1° 让并集家具掉 16 pp。
  - 树上 log-odds 求和比现行 max 规则高 5–9 pp（表面）、8–18 pp（家具）。
- 最薄弱的假设：用户接受"目标 = 干净传感器在真位姿下看到的东西"。
- 我的加强：不要预生成大噪声缓存，改为**GPU 在线传感器仿真**。缓存只存干净世界位图 + 位姿（每套 5–10 KB）。每步在 GPU 上重投射并加噪，约 10–30 ms，步时增加 5–15 %。噪声样本无限、零 CPU，几小时的 CPU 生成也省掉了。

## 2. 我攻击的 3 个论断

**攻击 1："干净世界里，学习型有损体素码还值得花 GPU。"**（A04 ΔV-Sheaf、A05 RAYFIELD 有损档与设计三、A03-B RK-Δ、A06 RayField、A02-G2、坐标阶梯，以及我自己第一轮的 W-Sheaf）

已实测的不学习前沿（字节均为中位）：
- 精确、F1 = 1：A03 收敛消息 317 B，A08 405 B，A10 510 B，A06 517 B。
- 只删不糊的有损：A03 删小盒 126 B，家具 .941（用真值分割，属于神谕点）；A08 167 B，家具 .93 / .95（平面分类用真值标签，只影响字节）。

这些学习型设计自己给出的预测：

| 设计 | 字节 | 家具 F1 |
|---|---|---|
| ΔV-Sheaf | 收敛消息 505 B | .73 |
| W-Sheaf（我） | 收敛消息 420 B | .72–.82 |
| RK-Δ | 360–600 B | .62–.68 |
| RAYFIELD | 自己的地图 145–175 B | .85–.93 |

每一个都落在 CPU 前沿内侧，严格被支配。按算力算，一个两周期两种子批是 4 个租约（8 GPU 小时），换来的点不如一个 0.3 s/图的贪心编码器。这些设计只有搬到噪声世界才可能有价值，那里精确码不再精确。

**攻击 2："网络层相对 gzip 十几到几十倍。"**（A10 α 对 gzip 洪泛 18.6×、加先验 27–32×、γ 48–67×；A07 D1 / D3 的 18× / 38–54×；A03 对现系统 46×）

这些数字把协议因子和编码因子乘在了一起。P6 把所有编码放到同一协议上比较（6 房均值，字节 / 房；与 A10 的 166,410 和 28,061 逐字一致）：

| 编码 | 洪泛 | 并集中继（每条有向边一次） |
|---|---|---|
| gzip-9 | 166,410 | 58,069 |
| ctx 三态 | 80,450 | 28,061 |
| S + 浮点位姿 | — | 15,624 |
| 重力填充世界 + 位姿 | — | 12,013 |
| 真值补全世界 + 位姿 | — | 9,124 |
| 现系统 | 229,376（8 轮定长） | 28,672（只发一次） |

- 洪泛到中继的协议因子是 **2.88–2.90×**，对任何编码都一样（就是 A10 的观测重数 μ = 2.87）。
- 同协议下，精确码相对 gzip 只有 **3.7–6.6×**，相对 ctx 1.8–3.0×。
- 正确写法是"编码因子 × 协议因子"。其中协议因子是 sheaf / GBP 网内融合**唯一被实测的**码率贡献，但 gzip 加同样的中继也能拿到它。现系统 229 KB 连 gzip 洪泛都不如。

**攻击 3：词元 / 槽位 / 程序类设计在这两周值得 GPU。**（A02-G3、A04 PR-Sheaf、A08 Vocab-Sheaf、A10-γ、A03-C、A01-Ⅲ，以及我的 C）

**码率上限很近。**

| 编码阶梯（自己的地图，精确，含位姿） | 字节 |
|---|---|
| 无结构的光线序事件码（A01，留一计数先验，含 13 B 位姿） | 263 |
| 平面图 + 盒子（A03 198 B + 浮点位姿差额约 19 B） | 约 217 |
| 生成器 DL + 精确位姿 | 约 120 |

- 程序层相对盒子最多省 1.8×；盒子再配学习先验（A03 估 130–160 B）后，余量只剩 ≤ 1.3×。
- 干净世界里 F1 已经是 1，F1 收益为 0。

**训练成本：**
- DETR 式匈牙利集合预测收敛慢。按 0.2–0.5 s/步，一个租约只有 1.3–3.3 万步，每个种子要多个租约，收敛与否不确定。锚点 / 中心投票式的稠密头（A08 的逐竖柱头、我的 CenterNet 式头）可行得多。
- 22 类家具库带来生成器泄漏（A07）。

**裁决：** 只做 CPU 神谕门槛。等旋转、噪声、留出家具面板存在后，再决定给不给 GPU。

**顺带两处算力纠偏**（不改结论）：A02-G1 约 0.16 s/步（自称 0.1 s）；A10-α 每步约 5.5 TFLOP，约 0.1 s/步（自称 0.07 s）。

## 3. 合成提案：LRS（分层光线 sheaf）

把 A03 的线路语言、A01 的光线序残差、A04 / A10 的新息协议、A02 / A07 / A10 的学习先验、A07 的噪声世界合成一个架构。

**索引集（公共、有界）：**

| 索引 | 范围 | 内容 |
|---|---|---|
| I_pose | 8 个智能体槽 | 3 个位姿；干净世界约 13 B，噪声世界为 SE(2)+z 高斯 |
| I_glob | 全局 | 墙高、门高 |
| I_plan | 128² 竖柱 | {⊥, 墙, 过梁} |
| I_vox | 128²×32 体素（信念层） | 格 {⊥ < 空, ⊥ < 占}；噪声世界为整数 log-odds ℓ̂ ∈ [−15, 15]（向零取整） |

盒子、残差事件只是线路语言，不是状态。

**能量：** Φ = Σ_i Σ_v [rk T*_v − rk s_i(v)] + Σ_i |A* ∖ A_i|。
- 中继"解码 → join → 规范重拟合"（A03）。新息与支配剪枝（A01 / A04）都不改变轨迹，所以 Φ 单调、≤ 直径轮归零。
- 有损只允许在源端删除一次（A06 / A08），此后都是无损 join，单调性不变。
- 噪声世界：树上整数求和是精确 BP，Φ = Σ_i |V_comp ∖ S_i|；位姿用块坐标 GBP（A07-D3 只取位姿部分），每步不增；有环时退回 CI-max。

**线路：** 头部 + 未发过的位姿 + 平面图（2D 上下文码）+ 盒子词元 + 光线序残差事件。概率全部来自同一个条件先验 p_θ（条件于平面图、位姿、腔状态），只发变化，按收集—分发调度。

**解码器：** 栅格化 → 整数 DDA 光线投射 → 三态图。干净世界里没有任何学习的解码器。噪声世界再加 MAP 去噪，编码端和读出端各一次；训练用我第一轮的射线终止损失。

**损失：** 干净世界只有码长 NLL；噪声世界 = 首次命中损失（对干净目标）+ λ·R。

**训练阶段：**
- S0：CPU 精确码，不训练。
- S1：计数先验。
- S2：神经先验，1 个租约，两种子。
- S3：噪声世界，GPU 在线仿真；去噪编码与 log-odds 树求和融合，4–6 个租约。
- S4：位姿配准层。

**预计（干净世界，收敛消息中位）：** 230–260 B（取 250），F1 全部 = 1.000（浮点位姿）。

| 对比 | 倍数 |
|---|---|
| 诚实最强无损（不学习的精确结构码，317 B） | 1.3× |
| ctx | 7.0× |
| gzip | 14.6× |
| 原始栅格 | 524× |
| 网络约 5 KB/房 vs 现系统 229 KB | 46× |
| 网络 vs gzip 中继 58 KB | 11.6× |
| 网络 vs gzip 洪泛 | 33×（其中 2.9× 是协议） |

**预计（cam 噪声世界，按真值）：**
- 自己的地图约 300–450 B，相对无损噪声图 ctx（2,472 B）5.5–8×，相对 gzip（4,570 B）10–15×。
- K0 表面 ≥ .94、家具 ≥ .83（地板 .918 / .775）。
- R8：配准成功时目标 .95 / .91，否则约 .90 / .80。

**学习在这个合成世界里还剩什么：**
1. **码率先验**：上限是 DL，现实增益估 1.2–1.6×，即每条消息几十到约一百字节。
2. **摊销编码**：把秒级的贪心搜索变成毫秒级，影响部署，不影响分数。
3. **去噪、配准、非盒子形状、真实数据迁移**：这才是学习的主战场，但现在的基准量不到它。

**结论：评估必须改。**
- 干净面板降为回归面板，硬判据是逐位精确。
- 主面板换成 A07 的 cam / lidar 噪声 + 机间坐标误差，加上旋转家具和世界、留出家具类别，目标为干净传感器在真位姿下的观测区，按真值评分。

**CPU 账：**

| 项目 | 成本 |
|---|---|
| 干净 TRAIN 缓存补浮点位姿、世界位图、物体表 | 4,708 套 × 5–7 s ≈ 8 核时，14 核约 40 分钟 |
| 预生成三档噪声缓存 | 约 47 核时（14 核约 3.5 小时）；改为 GPU 在线仿真则 0 |
| 旋转家具 | 生成器 v440 要做 OBB 格心栅格化，开发约 1 天，缓存约 40 分钟 |
| 留出家具 | 只是 TRAIN 过滤 |
| 面板（48 套 × 变体 × 2 个噪声种子） | 分钟级 |

真正的成本是开发：生成器 v440、与 `observe` 逐位一致的 torch 投射器、移植 A07 p3 的噪声模型，合计 1–2 天。

**我的前 3：**
1. **A03 RAY-SHEAF**：同分的精确结构族里实测最强，24 房、无标签。
2. **A07-D2 噪声世界**：它决定今后学习还有没有意义。
3. **A02-G1**：把生成模型放进熵模型和补全，是用户"压缩再生成"直觉的精确形式。

**建议的第一步实验 X0（纯 CPU，0 个租约）：**
- **单变量**：编解码器。精确结构光线码（A03 语言 + A01 光线序残差 + 计数先验 + 浮点位姿）对照"3S-X + 校准规则 + 诚实稀疏新息线路"（A04 实验 0）。

- **预注册：**
  - (i) 两个面板上全部自己的地图和全部 hop 目标逐体素精确 100 %，否则判为 bug；
  - (ii) 自己的地图中位（含位姿）≤ 250 B，收敛消息 ≤ 400 B，每房网络（收集—分发 + 新息）≤ 9 KB；
  - (iii) 两个半集先验的字节相差 ≤ 5 %；
  - (iv) 倍数必须拆成"编码因子 × 协议因子"报告。
- **预算**：uk-linux CPU 每段 ≤ 15 分钟，约 4 段。

X0 通过后，GPU 的第一个租约给 P1（神经先验 vs 计数先验，单变量，两种子同一租约）。两种子都 ≥ 0.95× 时，结论是干净世界里学习对码率也无贡献，全部 GPU 转向噪声世界。
