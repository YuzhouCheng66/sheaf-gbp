## 1. 能量与 GaBP

**消息公式**（g4_e3l.py 158–176）
- `lt = lam[s] + Σ_{k≠r} Λ_{k→s}`，`ht` 同理；`f = w/(w+lt)`；消息 = (ht·f, lt·f)。
- 信念 = 自身势 + 全部入消息；x = h_b/Λ_b，Λ_b = 0 时取 0（179–182）。
- 与 D8-54 的 Λ_{j→i} = wΛ̃/(w+Λ̃)、h_{j→i} = wh̃/(w+Λ̃) 逐字一致。
- 调度用 `G.forest` 的 `order`（按发送方一侧的大小升序）。每条有向消息只算一次，且只依赖更小的一侧，等价于任意根的收集—分发。

**独立实现核对**（`review_e3l/indep_gabp_check.py`，结果在 `indep_gabp_check.json`）
- 我的实现是纯 numpy 的递归记忆化消息，不借用实现的调度、`G.forest` 或任何 GaBP 函数。闭式解用显式 Laplacian 逐格稠密求解。

| 核对 | 规模 | 结果 |
|---|---|---|
| 自写 GaBP vs 闭式 (diag Λ + wL)⁻¹ diag Λ z | 300 棵随机树，m = 1–9，D = 1–8，w ∈ {1e-2 … 1e6}，40 % 的格子 Λ = 0 | 最大相对误差 **8.7e-10** |
| GaBP 点是能量最小 | 900 次随机扰动 | 能量增量最小为 +1.5e-3，没有一次更低 |
| 实现 `gabp()` vs 自写（浮点） | 200 棵树，D = 8，4×4×2 格 | 最大差 **4.3e-14** |
| 实现 vs 自写（整数线路，'round'，Λ_q = 0 ⇒ h_q = 0） | 268,416 个符号 | 非二进制有理的 w 下 **0 个不同**（另见 S4） |
| 接收方重算信念：自身量化势 + 收到的整数消息 | 全部 200 例 | 逐位等于实现的信念；每条消息都是整数，零精度格不携带 h |
| 实现的 `gbp_checks` | 同上 200 例 | cf_max 2.8e-11，单调违反 0（共 1,864 步） |

**能量单调**（O13，234–265）
- 定义为精确块坐标下降的读法：
  - 收集遍每步把一棵子树设为"给定父节点时的条件最优"；
  - 根上回代得到全局最优；
  - 分发遍逐台机器换成 GaBP 信念。
- 每步都是精确块极小化，所以单调是定理。这个断言真正检验的是"分发步的信念等于全局最优"：
  - 我给一台机器注入 +0.5 的错误信念，它报 1 次违反；
  - 正确时 0 次违反，终值与闭式解的能量差为 0。
- 单测 `test_naive_belief_sequence_not_monotone` 说明了为什么不用"各机当前信念"作迭代值。这个定义合理。主要分量仍在闭式核对上。

**闭式核对的范围**（211–224）
- 只比 ΣΛ > 1e-6·max(1, w) 的格子，与补充 5 里"只在有信息的格子上比"一致。
- 压力测试（`cf_stress.py`）设置：
  - Λ 处在截断下限 softplus(−8) = 3.35e-4 的格子占 3/4；
  - 8 台机器的链或星；w ∈ {1e3, 1e4, 1e5}；|z| 的标准差到 5,000。
- 结果：最大 cf_max 2.6e-6（星形、w = 1e3、σ = 5,000），36 种配置全过。下限格子在 w = 1e3 时 ΣΛ = 2.7e-3，会被纳入比较，同样通过。
- 误报只在隐码 |z| ≫ 5,000 时才可能出现（S6）。

**w → ∞ 与 E3-R 特例**
- 6 机随机树，Enc 取恒等（z = 整数证据，D = 1），Λ 取计数，走整数线路：
  - w ≥ 1e4 时，每台机器的信念 (h_b, Λ_b) 逐位等于 (S, k)；
  - 每条消息逐位等于发送方一侧的证据和与计数和，即 E1 的中继。
- 单测 `test_e3r_is_special_case` 还核对了 NET 的输入特征逐位相同。
- 注：初值 w0 = 1000 时不精确，因为 |S| 大的格子每跳缩 0.2 %。这符合"接近"特例的写法，特例本身是 w → ∞ 的极限。

**梯度**
- 直通量化与 GaBP 之下，被解码机器的损失对另一台机器（链的另一端）的 z、Λ 以及 log w 都有非零梯度。
- 截断：a = −50 时前向 softplus = 3.354e-4，反向梯度 3.354e-4，不为零。

## 4. 码率与对偶上升

**实现**
- 实测码长：第 1 次更新以及之后每 50 次更新，取被解码的 8 台机器的源端量化消息，按 O7 口径算码长（649–654）。R_meas 取最近 4 次的均值。
- λ 每次更新走一步：λ ← max(0, λ + 1e-3·clip(R_meas/R* − 1, −1, 1))，前 300 次更新 λ 保持 0（655–656、563–567）。
- 代理码长只提供梯度：
  - 编码器项 `detach=True`，冻结熵模型参数；
  - 熵模型项把输入 detach；
  - 支撑只计一次，即每格一个 Bernoulli 项（364–370）。
- R* = 8,000（115 行）。

**不会数值发散**
- λ ∈ [0, 1e-3·(U − 300)]。U ≈ 5,000–8,000 时，λ ≤ 5–8。
- 熵模型每个符号 ≤ 39.9 bit（P_MIN），损失有界。
- 全局梯度范数裁剪到 1.0。

**会不会让 Λ 全部失活**
- 不会永久失活。理由有三条：
  - 截断下限处的梯度是 3.35e-4，不为零；
  - Λ 的直通让 BCE 经 log1p(Λ_b) 的梯度在 Λ_q = 0 时仍然存在；
  - 一旦 R_meas < R*，λ 以每次更新最多 1e-3 的速度回落。
- 但**瞬时塌缩是可能的**。实现者的冒烟在 λ ≤ 0.009 时：
  - 支撑格从 3,280 掉到 294（12 次更新）；
  - 实测码长从 60.5 kbit 掉到 4.1 kbit（rate_curve.json）。
- 原因：Adam 的步长接近"按符号走"，只要率项的梯度在 Λ 头上压过 BCE，Λ 就以全速下降。λ 的大小只决定方向何时翻转，不决定速度。
- 正式运行时，前 300 次更新解码器先学会使用 Λ_b，情形会好一些。但 R_meas 有约 100–200 次更新的滞后，λ 可能超调；随后需要（λ 峰值 − λ 临界值）/1e-3 次更新才能退回。
- 结论：不会发散，可能振荡或出现阶段性塌缩。这属于预注册的设计（经协调者确认），不是实现错误。读数已经齐全：`rate_curve.json` 里有 support_cells、r_meas、λ，评估里有每台机器的 cells。改进见 S1。

**差距的量化**（两份冒烟）
- 初始源端每台机器 50–63 kbit，支撑 2,700–3,900 格。要压到 R* 需要降约 6–8 倍。
- 我的复跑冒烟只训了 6 次更新，接近初值。8 机单分量的 VAL 房 val_r1_i0_s1 每房字节 133 KB = **0.177 × 对照**（对照 752 KB）。
- 按线性外推，源端 8 kbit/机时约 20–35 KB/房，即 0.03–0.05 × 对照。
- 也就是说，R* = 1 KB/机比杠杆的字节线（0.15 ×）严 3–6 倍。这是预注册的选择，不改；但读结果时应注明，如果精度不够，部分原因可能是码率压得比判据需要的更低（S2）。

**远端可能出错的地方**（都已核对，未发现问题）
- `scripts/` 是扁平目录：g4_e3l 在 `HERE` 下导入 g4_e3r，评估的 worker 用 spawn 并通过 `G._worker_init` 设置路径，与 E3-R 同。

## 建议项

- **S1（可选，低风险）对偶上升下的 Λ 动态。**
  - 现在的截断是双向直通。持续受压时，截断前的 a 会在 −8 以下继续漂移（O2 自述冒烟里 24 步漂到约 −90）；λ 回落之后，要先把这段漂移走回来，Λ 才能恢复。恢复时间约等于受压时间。
  - 可选改法是"单侧直通"：a < −8 时只放行使 a 增大的梯度，需要一个几行的自定义 autograd。这样塌缩后能立即恢复，不改变前向，也不改变线路上可表达的内容。
  - 如果采纳，在 D8-54 补充里写一句，并重跑单测。不采纳时，结果报告里请画出 rate_curve 的 support_cells、R_meas 与 λ，并注明最后 20 % 训练中是否出现塌缩（例如支撑格的中位数低于初值的 10 %）。
- **S2 R* 与判据字节的关系。**
  - R* = 8 kbit/机，大约对应 0.03–0.05 × 对照字节，比杠杆线 0.15 × 严 3–6 倍（见 §4 的复算）。
  - 不改预注册；读结果时如果"不够"，应先看码率是否远低于判据所需，与 D8-54 "不够之后先做 CPU 诊断"一致。
- **S3 文档串过时。** `verdict()` 文档串（1197 行）写的是"fresh 符号相反 → AMBIGUOUS（LEVER / NOT_ENOUGH）"，与补充 4 和代码（1258–1263）不符。下次改代码时顺带修正；为此单独改动会改变 sha，不值得。
- **S4 整数线路在 .5 打平时的约定。**
  - torch 的"标量 / 张量"按倒数相乘实现（审查者复核：30/(30+3) 与 IEEE 除法差 1 ulp）。在 ht·f 恰为 .5 时，取整结果依赖这段算术：用二进制有理的 w（0.05、0.5、2、30、1000），审查者的 numpy 参照有 539/268,416 个符号不同；用非二进制有理的 w，0 个不同（`tie_rounding_trace.py`）。
  - 协议上无害，因为各节点跑同一段代码，接收方重算信念逐位成立。
  - 但 GPU 上选阈值与 CPU 上评估可能在个别格子不同。E3-R 也是 GPU 选、CPU 评，所以可以接受。
  - 可选：租约后把运行目录拷到别处，用 CPU 跑一次 `select`，只报告阈值是否一致。
- **S5 选阈值失败时的稳健性。**
  - `final.json` 在选阈值之后才写（693–705）。如果选阈值异常或被 kill，该种子只剩检查点 → INCOMPLETE。
  - 按 §7 的估算风险很低。可选的加固：先写 final.json 再选阈值；或者让链在缺 threshold.json 时于租约后用 CPU 跑 `select` 兜底。
- **S6 闭式核对的容差。** 它是绝对容差 1e-5。压力测试中 |z| 的标准差到 5,000 时仍有 4 倍余量。建议在 job 里同时记录相对误差，便于万一出现大隐码时区分"GaBP 错"与"闭式解病态"。
- **S7 吞吐提醒。** 编码器每个 batch 的机器数在 8–64 之间变化，开着 `cudnn.benchmark` 时每个新形状都会自动调优一次。这部分开销多数落在预跑和训练开头，已被预跑与 0.90 的安全系数吸收，只作提醒。
- **S8 只报告项与后续。**
  - D8-54 要求的"与 G4-E5 同图比较"不在 aggregate 里，事后作图即可。
  - 按 D8-55 后果 2，E3-L 采纳前须过 G4-H1 面板，请保留两个检查点与阈值文件。
- **S9 底线表述。** C2 的后半条"已知掩码与 B4 逐位相同"在 E3-L 中按 D8-54 换成"学习的已知头 + FPR 保护"。结果报告里应明说：这是本批与 E3-R 在底线表述上唯一有意的不同。
