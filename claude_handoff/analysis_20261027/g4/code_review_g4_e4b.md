  逐机位置误差中位数，E4b 在其中两房更好（7.7 对 8.1 cm，2.4 对 3.5 cm），一房略差（6.6 对 6.1 cm）。在 TRAIN r2_i3 上，边 (2,7) 成对门控拒绝、侧消息门控通过，正是 D8-40 预期的机制。

## 1. 七个核查点

### 1.1 单变量与"第一遍复现 E4"的单测：成立，单测有效

**边因子输入的实现，与 D8-40 的定义逐项对得上：**
- `tree_sides`（`:106-124`）：
  - 对每条树边 (i, j)，B_e 是 j 的子树，A_e 是"连通块减去 B_e"；
  - 边按子节点的 BFS 顺序排列（从根向外）；
  - 单测 `test_tree_sides` 断言两侧不相交、并起来是整个连通块、i ∈ A、j ∈ B。
- `_side_surfels`（`:138-147`）：
  - 取该侧各成员自己的 E4 surfel（`R.evidence(R.planes_logodds(L))`，与 E4 同一个调用）；
  - 质心按当前修正 C_a 移动，法向按 C_a 的旋转转动，权重和有向标志不变；
  - 然后拼接（取并）。这就是 D8-40 的 S(·)。
- `message_energy`（`:127-135`）：E_msg = Σ_e `R.edge_cost(S(B_e), S(A_e), I)`。两侧都已在公共坐标系里，形式和常数都是 E4 的（对称截断点到线）。
- 局部两步就是 `R.register_pair(side A, side B)`（`:165`）：相关式扫描候选加 ICP，只接受让本边项下降且过门控的步，没有复制或改写。

**其余环节都直接调用 E4 的函数：**
- 匹配器常数：`opts['match'] = dict(R.MATCH)`，指纹里的数值与 E4 相同；
- 门控：`R.gate`；
- V3 重积分：`R._integrate`；
- 森林求和与计分：`R.eval_arm`，三行 asis / aligned / aligned_best；
- prior 规范：`R.gauge_fix`，pivot 与 E4 一样，取信念坐标系 surfel 的质心；
- 真值臂：`R.compose` / `R.truth_deltas` / `R.islands_K` / `R.observability_islands`，用的是同一组 pivot 和 surf_m。

`run_job`（`:196-320`）与 E4 的 `run_job` 逐行对照，只有以下差异：
1. `register_forest` 换成 `register_messages`；
2. 不再算 E4 的只报告行 `asis_rootgauge`（S6）；
3. 真值臂复用检查不再把 `reg` 列为候选；
4. 每条边报告的 `disp_pivot_cm` 换了 pivot（S5）。

第 2、3 条都不影响判决行。冒烟里 `rows vs E4 {'equal': 6}`、G4-E1 比对 2/2 相等、oracle_all 收回 1.011，与上述差异一致。

**单测 `test_two_agents_one_sweep_equals_e4`（`test_…:81-89`）有效：**
- 只有一条边时，A = {i}，B = {j}，C = I：
  - `warp_plane` 在 M = I 时原样返回 w；
  - `apply2(I, m)` 与 `n @ I` 在浮点下逐位不变；
  - 所以 `register_pair` 收到的输入与 E4 逐位相同。
- 单测断言 C 与 K 逐位相等（`np.array_equal`）。
- 单测还断言 `len(E_msg) == 2`，也就是确实采纳了一个非恒等的更新。若两边都停在恒等，这条断言会失败，所以不是空测。

### 1.2 优化与能量：忠实于 D8-40；单调断言完整；没有直接自匹配

**顺序与接受规则（`:162-179`），与 D8-40 一致：**
- 固定两遍，每遍按从根向外的 BFS 顺序逐边；
- 局部一步由 `register_pair` 保证本边项严格下降且过门控；
- 候选状态把 B_e 的全部成员左乘 Δ；
- 重算全局 E_msg，严格更低才采纳，否则退回。退回不需要恢复：C 没有被改动，`Cn = dict(C)` 是浅拷贝，矩阵是整体替换而不是原地修改。

**单调断言（`:180`）：**
- 轨迹 = 初值 + 每次被采纳状态的全局 E_msg，每个值都是从头重算的。
- 最终的 K 只是对 C 做整体刚体变换（规范），E_msg 不变。
- 因为采纳条件是严格 `<`，这条断言在构造上不会触发（E4 也是这样）。建议加一条"对终态重新计算一次 E_msg，应等于轨迹末值"的检查（S4）。
- 审查者的独立重放（`diag_e4b.py` 第 2 步）在两个冒烟房子上逐位复现了任务文件里的轨迹。

**自匹配（R-C 风险点 4"位姿步用含本子树证据的信念配准"）：**
- 没有直接自匹配：
  - A_e ∩ B_e = ∅（有单测）；
  - 消息是成员自己的 surfel，不是融合后的信念；
  - 配准后各机用自己的光束在 K_a 下重积分再森林求和，没有对已融合信念重采样（风险点 5 也不存在）。
- 有一种间接回声，属于方法本身：
  - A_e 里成员的当前修正，是在更早的边（兄弟子树、第二遍的全部边）上估计的，那时的配准目标里含有 B_e 的证据；
  - 所以 S(A_e) 不是精确树 BP 意义上"与 B_e 无关"的消息；
  - 这是 D8-40 选定的块坐标下降的固有性质。D8-43 第 5 条已写明，这类方法"只能声称每轮结束时能量不增"。它倾向于把早期状态锁住，与 §0 的死锁同向，但不是死锁的主因。

**侧平面取逐像素最大（`:99-103`），合理：**
- D8-40 没有规定相关式扫描用的平面。逐像素最大与 E4 全数据上限（islands）里的合并证据一致；用求和会让多机都看到的墙权重加倍。
- 平面只用于粗搜索的候选；候选能否采纳，由 surfel 能量和门控决定。
- `warp_plane` 的索引公式审查者逐项核对过，正确，单测也覆盖了平移和 90° 旋转。

**能量的一个性质（方法本身，记录在案）：**
- 一对智能体 (x, y) 的匹配项，在树上 x 到 y 路径上的每条边里各算一次，所以越深的智能体权重越大。
- 冒烟里 (6,5) 被退回，部分原因就是 7 对其余智能体的项在 (6,5) 和 (5,7) 里各算了一次。

### 1.3 子树刚性移动的复合：正确，不会重复施加；与 prior 规范没有冲突

- 方向约定：
  - `register_pair(evA, evB)` 返回的 Δ，把 B 侧（公共坐标系）映射进 A 侧（公共坐标系），与 E4 的 `register_pair(ev_i, ev_j)` 约定相同；
  - 能量 `edge_cost(S_B, S_A, ·)` 也是同一方向。
- 复合：
  - C_b ← Δ C_b 对 B_e 全体成员左乘。B_e 内部的相对位姿 inv(C_b1) C_b2 不变；
  - 树边 (i, j) 两端的相对位姿，只会被这一条边改变，所以 `corrected = kept > 0` 准确反映这条边。
- 第二遍：Δ 从当前状态重新估计，是增量，不会重复施加。信赖域（10° / 0.6 m）是逐步的，两遍累计最多翻倍，对 cam 档的误差量级（约 5 cm、1°）没有影响。
- prior 规范：
  - E4b 只移动子侧，所以未规范的 C 漂向根的坐标系；
  - `R.gauge_fix` 用 E4 的同一组 pivot 取平均再整体回移，E_msg 不变，处理方式与 E4 相同。

**问题在移动集合本身，不在复合的实现：**
- "修正 Δ_e 把 B_e 的全部智能体刚性地移进 A_e 的坐标系"，加上"每条边后全局 E_msg 不降就退回"，使得"内部节点偏了、它的后代没偏"这种状态无法修正：
  - 动这条边会把后代拖走，被全局退回；
  - 动后代的边只是让后代去贴整栋房子，后代本来就贴得好，所以不会动。
- E4 的参数是相邻两机的相对位姿，再沿树复合，没有这个问题。
- 冒烟 VAL r1_i0 的数字见 §0（`review_e4b/diag_VAL_r1_i0_s1_cam.log`）。

### 1.4 整侧消息覆盖整栋房子后，门控的语义：分母没问题，内点数略宽松；冒烟里多出的未修正边是全局退回，不是门控拒绝

**分母：**
- 门控的权重比例取 `max(wf, wr)`，即覆盖较好那一侧的内点权重比例。
- 小侧对大侧时，取的是小侧自身被匹配的比例，不会被大侧稀释。实现者在文件头 `:39-40` 的说法成立。

**审查者在 4 房 × 7 条树边上，用 K0 证据在真位姿处比较了三种门控：**

| 门控 | 通过 / 28 |
|---|---|
| 成对（E4 的 overlap_true） | 20 |
| 侧并集（E4b 的形式） | 22 |
| 侧合并平面（E4 islands 规则） | 21 |

- 并集比成对多通过 2 条：TRAIN r2_i3 (2,7)、TRAIN r3_i2 (7,5)。
- 并集与合并平面在 27/28 条边上判定一致，只有 (7,5) 是并集通过、合并平面拒绝。
- 没有一条边是"成对或合并平面通过、并集拒绝"。所以不存在过度拒绝。

**略宽松的来源：**
- 并集里多台机器看到的同一面墙会重复出现，所以"每个方向 ≥ 50 个内点"的计数被放大，例如 385 对 258、325 对 197。
- (7,5) 在并集下 n_inl = 53，刚过 50；按合并平面只有 33。
- 这是沿用 E4 冻结数值的直接后果。D8-40 只允许在 TRAIN 上发现必要时改常数，这里没有足够证据，也不建议改。建议在报告里写明（S2）。

**冒烟的"未修正边 2/14 对 1/14"：**
- 两种方法的门控拒绝都是 1/14：VAL r1_i1 的 (6,3)，三种门控在真位姿下也都拒绝。
- E4b 多出来的那一条是 VAL r1_i0 的 (6,5)：局部一步过了门控（n_inl 309，比例 .82），两遍都被全局退回。
- "逐机位置误差中位 5.9 对 4.4 cm"也主要来自这一处：智能体 5 留下 17 cm；逐机误差是去掉连通块均值之后算的，这一机的偏差也会抬高同一连通块里其余各机的误差。

**cam_nf 上 −0.49 pp：** 不是缺陷。
- 冒烟两房 cam_nf 的逐机误差，E4b 与 E4 相当或更小：r1_i1 是 [3.1, 3.0, 3.5, 1.3, 2.5, 2.8, 1.3, 5.4] 对 [4.3, 3.3, 2.8, 1.3, 3.4, 2.6, 1.3, 6.3]。
- 两房上 F1 差 0.7 pp，在单房噪声量级内。E4 在全 VAL 上也有 −0.34 / −0.42。
- 正式运行若在这条保护线上失败，那是预注册允许出现的合法结果。

### 1.5 判决逻辑与 D8-40 逐字对照：一致；有两处遗漏（M3）

**与 D8-40 一致的部分：**
- 每个面板（VAL、fresh）都调用 `R.verdict(…, judged=True)`（`:473`），给出 D8-39 的读数：
  - 收回 ≥ .85；
  - E_msg 单调；
  - cam_nf ≥ −0.5 pp；
  - 空闲召回不降；
  - FPR ≤ +0.3 pp；
  - 两种子都要满足。

  fresh 也是 judged=True，因此 fresh 的 cam / cam_nf 也必须与 G4-E1 逐行相等（e1/jobs 里 VAL、fresh 各 48 个任务文件，都在）。
- `verdict_e4b`（`:426-440`）：
  - 两面板都是 LEVER，才判 LEVER；
  - VAL 判 INSUFFICIENT（两种子都 < .50），就判 INSUFFICIENT，不看 fresh；
  - 其余判 AMBIGUOUS。

  与 D8-40 一致，单测覆盖了这些组合。
- INCOMPLETE 的条件：缺种子、两种子房子集合不同、缺房、任务失败（`extra`）、与 E1 不等或缺比对（`R.verdict`），加上与 E4 不等或缺 E4 任务文件（`e4_cmp_reasons`）。
- 机制读数 `mechanism`（`:393-414`）：
  - 只用 VAL cam，与 E4 在同一组（房子, 种子）上比较；
  - 收回用 `R.recovery_distribution(...)['pooled']`。审查者核对过，它在 E4 正式任务上给出 .15323 / .33506，与 E4 判决行的数值一致到 1e-14；
  - "两种子都 < +.15 → 不成立"的方向正确。

**遗漏：**
1. 补充第 1 条（oracle_all 偏离 1 超过 .10 时，判词标"对齐流程自检失败"）和补充第 4 条（对齐取较好者一行判出的档位不同时，注明"对对齐敏感"）的标记，只留在各面板的 `verdict` 文本里。E4b 的最终判词 `decision.verdict` 没有带上，也没有按 E4b 的规则（VAL 与 fresh 都满足才算 LEVER）在 aligned_best 行上重判一次。
2. 不给 `--e4-out` 时，`e4_compare_job` 返回 `no_e4_dir`，`:470` 的 `if e4_dir and bad` 直接跳过，不会判 INCOMPLETE；机制读数也会变成 None。"与 E4 行不等"是 INCOMPLETE 条件之一，缺比对应当同样处理。

**机制读数的口径问题（M2）：**
- `_edge_frac_uncorrected`（`:381-384`）把"全局退回、始终没被采纳"的边也算作未修正。
- D8-40 的原文是"门控拒绝、只能保持不修正的树边比例"，检验的是"消息让更多边过门控"这一机制；全局退回是另一种机制（优化器死锁）。
- 任务文件里已经逐边存了 `no_local_step` 和 `rejected_global`，只需要在汇总时拆开。
- E4 全 VAL 的未修正比例是 .275 / .299（167 条边），E4b 要"至少减半"，需要 ≤ .138 / .150。

### 1.6 位姿层消息的字节数：每条消息的算法是诚实的；有三点要写清（S3）

- `msg_bytes_up = 6 × n_B`，`msg_bytes_down = 6 × n_A`（`:259-264`）：
  - n 是该侧各成员 surfel 数之和，与 E_edge 实际用到的点数一致，没有去重，也没有压缩；
  - 每个 surfel 6 B，正是 D8-40 写死的公式。
- 树上一条边就是一跳，所以每房合计 Σ_e 6 (n_A + n_B) 是一次交换在各条链路上的流量。冒烟中位数约 85 KB / 房，是 S0 的 14 倍。
- 要写清的三点：
  1. D8-40 原文问的是"每条消息……以及它占 S0 一次融合 6.1 KB 的比例"，但代码只给了每房合计除以 S0（`:423`）。应补上"每条消息中位数 / S0"，冒烟中约 0.97。
  2. 每房合计只算了一遍交换。第二遍要么重发，要么只发各成员的修正（每机 3 个数），报告应当注明。
  3. 6 B 的编码里没有"有向 / 无向"标志位，可以借用权重字节的最高位，字节数不变。另可给出 E4 成对协议的字节数作对照：每条边 6 (n_i + n_j)。

## 2. 必改项（运行前）

## 3. 建议项

- **S1**（不放进本批）：
  - 若 M4 的读法最终判"受优化器限制"，下一步应另写预注册（E4c），只在 TRAIN 上开发，fresh 作为守门。候选做法：
    - 从 E4 的解出发，再做同样的消息扫描。这样 E_msg 不会高于 E4 的解；
    - 或者在全局退回时，回退成"只动子节点"的一步。
  - 不建议现在把它作为臂加进 E4b：它是看过 VAL 冒烟后设计的，加进来会混淆本批的单变量。
- **S2**：每条边加只报告的"侧可观测性"：在真位姿、用 K0 证据，分别计算侧并集门控和侧合并平面门控（§1.4 的表）。这样可以回答"成对不可观测、侧可观测的边，E4b 修正了没有"。同时在报告里写明：并集的内点计数因重复 surfel 偏宽松。
- **S3**：字节数按 §1.6 补充：每条消息 / S0、两遍的说明、有向标志位、E4 成对协议的字节数对照。
- **S4**：
  - 每条边每一遍的局部轨迹 `res['traj']`，也调用 `R.assert_monotone`，与 E4 保持一致；
  - `register_messages` 结尾对终态重新计算一次 E_msg，断言等于 `traj[-1]`，让断言能捕捉记账错误；
  - 都只增加几十毫秒。
- **S5**：
  - 每条边的 `disp_pivot_cm` 用的是 j 的 surfel 质心作 pivot，E4 用的是重叠 pivot，两者不可比；E4b 与 E4 对照时只用 `disp_rms_cm`。
