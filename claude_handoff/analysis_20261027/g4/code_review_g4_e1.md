但有四处与 D8-36 不忠实，或判决代码有漏洞，必须先改：
1. 积分器（M1）；
2. 判据 (c) 的比较对象（M2）；

## 1. 实现者自标风险的逐条裁决

### R1 积分：不忠实，必须改（M1）

**现实现（记作 V0）**：每次扫描内把逐束计数相加，即 L ← clamp(L + 17·n_hit − 8·n_miss)，每次扫描只截断一次。

这不是 OctoMap 的任何一种用法：
- OctoMap 的 `updateNodeLogOdds` 在**每一次**节点更新后截断；
- 一个体素在一次扫描里要么只更新一次（`insertPointCloud`），要么每条射线更新一次（`insertRay`）。

"先求和再截断"两者都不是。在近处，一个体素每次扫描被几十条射线穿过，求和让截断几乎总是生效。于是每次扫描的结果近似退化成"命中率 > 8/25 = 32 % 就占据、否则空闲"的符号投票。这个规则是 V0 自己造出来的。

**两种忠实读法：**

- **V1（OctoMap `insertPointCloud`，就是任务说明里举的例子）**：
  - 每个位姿一次扫描。
  - 扫描内，一个体素若有任何端点落入，就记一次命中（+17）；否则若有射线穿过，就记一次未命中（−8）。占据键从空闲键集合里删掉。
  - 每次更新后截断到 [−40, +70]。
- **V3（OctoMap `insertRay` 逐束）**：
  - 每条射线是一次测量：穿过的每个体素记一次未命中，端点体素记一次命中。
  - 射线按 Fibonacci 下标顺序，扫描按位姿顺序。
  - **每一次**更新后截断。
  - 它和 A07 p3 的定义"一条射线每个体素记一次未命中，端点体素不记未命中"完全一致，只多了 D8-36 加的截断。C1 的噪声复核、A10 也都沿用 A07 的定义。

**另有 V2**：逐束、不截断，就是 A07、A10、C1 探针的做法，也是 D8-36 事实 6 那些数字的来源。

**审查者的推荐：判决用 V3，V1 作为必报的敏感性行。** 理由：

1. **文本链。** D8-36 的"OctoMap 式 log-odds 积分"逐字来自 C1 表，C1 表来自 A07。A07 明确把"OctoMap-style"定义为逐束（"one miss per voxel per beam"）。D8-36 新增的只是"按 OctoMap 默认上下限截断"，而 OctoMap 的截断语义就是每次更新后截断。V3 同时满足这两句话。
2. **阈值的标定范围。** (b) 的 .85 和止损的 .92 是按逐束积分的探针数字定的（cam R8 求和 .78–.91）。在 V1 下，地板整体塌到 .33（见下表）。阈值在那里没有区分力，(b) 的家具臂必然成立，止损必然不触发。这等于换了一个实验。
3. **V1 本身没有错**，它是真实 OctoMap 在"每个智能体只有 3 次稠密扫描"时的行为：
   - 3 次扫描里任何一次有端点，L 至少是 17 − 2×8 = +1，就判占据；
   - 测距噪声把地面上方一层空闲体素大面积标成占据，这一层在家具区里。
   - 如果用户认为 V1 才是本意，那属于修订预注册：需要用户拍板，并重新标定阈值，不能由实现者自行决定。

### R2 B5 的做法：部分不忠实，必须补（M3）

D8-36 写的是"log-odds 阈值 × 删盒 m ∈ {4, 8, 16, 32} × {1, 2×2×1}"。C2 和 A07 辩论稿写的是"盒拟合最小支撑 m"。来源是 A03 p3/p12 的有损盒码：贪心实心盒覆盖观测命中，只保留覆盖 ≥ m 个命中的盒（C1 F13：m = 32 时 108 B / .857）。

实现用"删掉小于 m 的 26 连通块"代替"删盒"。两者不等价：
- 连通块删除只去掉悬空的散点；
- 删盒会去掉贴在墙面或桌面上的小凸起，也会删掉细腿和薄层。

逐项裁决：
- **阈值网格**：τ ∈ {0, .85, 1.7, 2.55}，按 0–3 次命中的步长取，合理。它在 V0/V3 下有意义。若改用 V1，τ = 2.55 用严格 ">" 永远为空，应改为 "≥"（S4）。
- **融合**：中继 ±1 投票和、占据优先，与 D8-36 的"两种融合（森林求和 / max）"对应，可以接受。另外建议加一个非对称投票（占据 +17、空闲 −8），见 S3。
- **凸包**：按时间分享读凸包，`hull_value` 的实现正确（单测覆盖）。凸包同时包含两种融合，让 B5 更强，对"学习空间"的判断是保守的，可以。
- **编码**：B5 用三态 ctx，而不是 A03 的结构码加接收方光线投射。在 ¼B4 的预算下（约 120–260 KB），64 个配置几乎全部低于预算，所以编码器只影响字节、几乎不影响凸包读数。可以不改，但要在报告里写明。

**实测（M3 的影响）**：用 G4-E0 的 `box_cover`（A03 原样拷贝）实现预注册的删盒族，其余流程不变，V0 积分器，cam，4 个房子（`review_e1/r2_b5_box_probe.json`）：
- B5 凸包 @¼B4：连通块族 .715，删盒族 .725，并集 .725。
- B4 是 .752，所以 B5 臂在三种取法下都成立，余量约 4.7 pp。
- 两族最好的配置都是 τ = 0、m = 4、全分辨率、投票求和。也就是说，阈值和删除几乎帮不上忙，B5 与 B4 的差主要来自"三态投票"对"log-odds 求和"。

结论：必须把删盒族补上（这是预注册的定义），凸包取两族的并集。并集只让 B5 更强，对"有学习空间"的判断是保守的。

### R3 "max"取 |ℓ| 最大者：判决应改用 max_occ（M2）

- D8-36 写的是"两种融合（森林求和 / max）"。它引用的证据全部是"占据优先"的 max：A10 的 .844 → .557，C1 的 .909 对 .780。干净档的 `rollout_max` 和 `stream_targets` 也是占据优先。
- 对整数 log-odds 逐体素取 max ℓ，它的三态读出与 `max_occ` **逐体素相同**：只要有一个智能体 ℓ > 0，就占据。所以字面的"max"就是 max_occ。
- maxabs（最大置信）是预注册之外的第三种算子，而且在截断积分下会被不对称上下限扭曲（见 R1）。

结论：
- (c) 的判决用 max_occ；maxabs 照常报告，作为更强的幂等对手。
- 如果协调者坚持用 maxabs 判决（"按指令"），必须在运行前写成对 D8-36 的修订。
- 只报两者、不指定判决用哪个，不够：在 V1、V2 下两者给出相反的 (c) 结论。

### R4 公共随机数、z 误差 σ/2、绕智能体中心旋转：可以

- **公共随机数**：标准变量按（噪声种子、房子、智能体、位姿）抽取，与档位无关，再按档位的 σ 缩放。漏测用同一个均匀数加阈值，所以档间单调耦合。
  - cam 与 cam_nf 因此是配对比较。"cam 在真机间位姿下"就是 cam_nf 的图，单测已断言。
  - 两个噪声种子仍是独立重复。这只减少档间差的方差，不影响判决的独立性，可以。
- **z 误差和旋转中心**：
  - 逐帧 x、y 各 σ，z 取 σ/2，只有偏航误差，这与 A07 p3、C1 的 `measure` 逐行一致。
  - 机间误差是 SE(2)：绕智能体中心旋转加平移，z 不动。A07 用 3 个位姿的均值作中心，实现用未抖动的中心 `positions_m`，两者相差 ≤ 0.1 m，在 1° 下多出 ≤ 2 mm 平移，可以忽略。
- **K0 与 R8 的扫描**：K0 和 R8 用同一组扫描，R8 只是在扫描几何上加机间误差后重新积分。这比 A07 给 K0、R8 各抽一次噪声更一致，可以。

### R5 B4 编码器、359 KB、中继、S0 常数、(b) 的分母、(a) 的检查

- **编码器**：三态 ctx 加幅值流（同态邻居相等标志、exp-Golomb 二值化、自适应 KT）。单测证明码长等于逐符号顺序的自适应编码器。解码顺序也是因果的：先三态，再按光栅序解幅值，预测邻居都已解出。所以它是合法的无损码。
  - 没有真实区间编码往返（S8）。
  - 幅值流占 B4 字节的 85–90 %（V0 cam：三态 ctx 中继 72 KB，B4 495 KB）。
  - 编码器偏弱只会放大 ¼B4 预算，让 B5 更强，对 E1 是保守的。但会让 E3 的"R_net ≤ ¼ B4"更容易达到，所以建议做强度对照（S7）。
- **干净档 359 KB 与"ctx 与结构码取小"**：实现的 B4 没有"结构码"分支。在干净档：
  - S0（命中集 + float32 位姿，接收方用公共射线光线投射）不只重建三态，还能逐束重算每个体素的命中和未命中次数，因此能精确重建整数 log-odds 图（任何一种积分器都行）。
  - 所以按预注册，B4_clean = min(359 KB, S0) = S0。D8-36 (a) 写的"clean 档 B4 与 S0 一致"，以及 A07 原设计里的"B4 自己地图 ≤ 300 B，R_net ≤ 9 KB/房"，指的正是这一点。
  - 现在 (a) 只检查了地图一致（逐体素精确、空闲召回 = 1、FPR = 0、三态准确率 = 1）。这一半是必要的，也做对了。字节的一半没有体现：summary 里的 `clean.rnet_median.B4_relay` 是 359 KB，会被误读。见 M4。
- **(b) 的分母**：用 S0 是忠实的，原因有二：
  - 原文写"干净档 S0"；
  - 按设计 B4_clean ≡ S0，两种读法本来就重合。
  - 用 B4 整数编码器自己的干净档字节作分母是不忠实的：那个数是缺了结构码分支造成的假象。
  - 后果要如实报告：字节臂远不受约束。B4_cam / S0 约 82×（V0），在 V3 下约 92×。这个"字节空间"主要来自传输 log-odds 幅值，不来自噪声本身。B4_int(cam) / B4_int(clean) ≈ 2.4×，只作信息报告。
- **中继还是洪泛**：判决用中继，与系统协议一致（S0 的 6.1 KB 也是一次森林融合），也与 B5 的 ¼ 预算口径一致，可以。`B4_best_info = min` 照常报告。在 4 个房子和 2 个冒烟房子的 cam 档里，中继都更便宜，所以这一项不改变判决。
- **S0 常数 6,066 B**：来自 D8-36 事实 2（24 个 VAL 房子的中位），可以。字节臂离阈值有两个数量级，换成 G4-E0 实测值也不会改变任何结论（S5）。

## 4. 建议项

- **S1**：(c) 的"FPR 不劣于 +0.3 pp"在三种融合下恒为 0（已知集都是并集）。建议另报"真值空闲但预测占据"的比例作为实际的护栏。判决仍按原文。
- **S2**：凸包的横轴是各配置字节的中位数，纵轴是 F1 的均值。时间分享在严格意义上要用均值字节。建议同时报"均值字节"版本的凸包读数（判决不变）。
- **S3**：B5 加第三种融合：非对称投票（占据 +17、空闲 −8，相当于把每个智能体的三态当作一次 OctoMap 更新）。它介于 ±1 投票和占据优先之间，加入并集凸包只会让 B5 更强。
- **S4**：B5 的 τ 若用于 V1 敏感性行，改为 "≥ τ"（τ > 0）。否则在 V1 下 τ = 2.55 为空集。
- **S5**：S0 常数改为 G4-E0 在同一批 VAL 房子上的实测中位（如果已有）。在 summary 里注明来源。
- **S6**：`--aggregate-only` 会覆盖 `run.json`。冒烟的 `run.json` 记的 workers 是 6、用时 0.25 s，而真正的冒烟是 2 个工作进程、383 s。建议聚合写 `aggregate.json`，`run.json` 只在真正运行时写。
- **S7**：B4 编码器做一次强度对照，例如对同一批消息比较 lzma、zstd-19 和一个以邻居幅值类为上下文的多符号 KT。这是为 E3 的"≤ ¼ B4"准备的，不影响 E1。
- **S8**：可选。用 G4-E0 的区间编码器，对 2–3 条 B4 消息做真实往返，确认码长与实际字节相差不超过几个字节。
- **S9**：B1 另报"三态 gzip 洪泛"，便于和 D8-36 表里的"gzip 洪泛 27×"对照。
- **S10**：报告里写明，这 4 个房子的 (c) 对 maxabs 的增益逐房波动很大（V0 下 r3_i0 只有 +1.4 pp），所以对 maxabs 的 +3 pp 要看 24 房的均值，单房不稳。
