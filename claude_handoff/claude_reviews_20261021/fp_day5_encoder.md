## 1. 第一性原理：R8 .89–.90 的残差由什么决定

推理链（每步：证据 → 结论）：

1. **融合不丢信息。** 理想同态（编码器直接编码"已到达来源的并集观测"）与实际 max 后验差 ≤ 0.4 pp（D4-10 表）。⇒ R8 残差 = "K0 型残差作用在更大、更完整的区域" + own-drop；任何只改"谁赢"的改动（含改 q）上限 ≈ 0.4 pp。
2. **不是 bit 数。** 自由码协议 16 bit vs 8 bit 上限 .814 vs .819（D4-11）；训练系统的 k-bit 曲线 6–8 bit 平坦、5 bit −3.7、4 bit −12（D3-6 表；D3-12 Phase D）；码的经验熵 H(μ) = 5.4–7.6 bit（D3-6；D4-14 表）——8 bit 没用满。
3. **不是"摊销编码器找不到码"。** v384 K0 .918/.920（BEST_RESULTS §1）已**高于**同协议自由码上限 .819（D4-8 M2）：逐样本优化 + 4000 步解码器低估联合训练；编码器只有 236k 参数（866k − 630k，BRIEF 第 50 行）却不是短板。
4. **是每块的"词汇量"。** 每块一个标量经 tanh→hard-8（L154，L241-244），解码器把标量平滑地映射成图案（D4-11 结论）；块越满越差：8+ 室 R8 .82–.87 vs 2–4 室 .92–.94（BEST_RESULTS 分层表）；16×16×1 上限 .918 vs 8×8×1 .819（D4-6 表）——块边长减半 = +10 pp 表达力。
5. **q 已经是第二个内容通道（事实，非指控）。** 学到的 q 与覆盖率 Spearman .91 但超线性（N2-0）；去掉精度头（q = 4×覆盖）R8 −4.7 pp（N2-1 cov 臂）；μ6q4 −11 pp vs μ6q5 −2 pp（D3-12 Phase D）⇒ 解码器从 q 读到 ≥ 5 bit/块，而纯覆盖置信 ≤ 3 bit 足够；解码器把 log(1/P)/8 当整面平面读（L196）；能量复审早已指出"q 不能同时是门控和内容"（energy_restriction_gbp.md §2(d)）。**事实上的瓶颈是每个被观测块 ≈ 8 + 5 bit、join 以第二个数为键。**
6. **残差像素形态**：门洞两侧短墙桩、窄开口、大户型薄内墙（BRIEF 第 36 行；`figures/houseexpo_best_v383_panels.png` 第 3、6 行）；v293 上精确 F1 与 1-px 容差 F1 相差 ~5 pp（D3-3 表）。都是"块内子结构需要自己的词条"或"标量索引图案的位置精度"。

**结论**：编码器侧只剩一个杠杆——**让标量的选择知道它将在什么上下文中被解码**（局部精修或邻域上下文），以上下文倍增词汇量；但 max 融合的马赛克会对此征税（§3）。精度通道没有"更有信息"的余地（它已是内容），只有"更纯"的余地（要付 ~5 pp）。

## 2. 四个角色问题的直接回答

**(1) 分析-综合编码（v387 正在测）。**
- 它测什么：以训练损失（known BCE + DT L1，L389-396）对自身观测优化 64 个 μ，q 固定、未观测块乘 mask = 0（L594-608；v342 复审第 8 项的 mask 缺陷已在 L601 修正）。它测的是"编码器相对解码器的摊销差"；但编码器被训练的是 K0（权 .5）+ 四个融合阶段（权 .5，L31），K0 的次优中有一部分是**刻意的融合折中**，不是失败。
- 预期（依据 v293 轨迹）：K0 增益随训练递减——+5.8 pp（8 ep，K0 .80；root_ledger.md L40）→ +2.1（36 ep，.910→.931；OVERNIGHT L27）→ H256 +3.1 / +2.2（L41 / L69）；而 R8 **−1.3**（L27：.848→.835，FPR +.4 pp）、H256 **−1.2**（L41）。【预测】v384：K0 +1.5 ± 1 pp，R8 −1.5…0 pp，落在 BRIEF 第 56 行预注册判读的模糊带（+1…+3）。
- 与 max 融合的相互作用（机理，可证伪）：解码器是 CNN，块 k 的渲染依赖邻块码（L189-201）；精修使 μ_k 与**自己的**邻块码共同适应，R8 时赢家的 μ_k 却落在别人的邻块旁——D3-3 已量化这种错配（同一块码在 K0 上下文 69% 对、R8 上下文 52% 对）。此外，精修把"我没看到的半块"推向 unknown（known BCE），而 max 丢掉败者后解码器本靠邻块补回 .887 recall（D3-4(b)）；精修后的赢家码更"自信地空"。所以 **K0↑、R8↓ 是结构性的**，不是噪声。
- 训练方式：(a) 用精修码训练解码器：每 agent 每更新 50 次 fwd/bwd ⇒ 一个租约只剩 ~1/50 的更新，K = 5 也只有 ~11.5k 更新；历史 v233（精修码作目标，两臂都选 step 0）失败（encoder_information.md L111）。(b) 半摊销：v265 训练版没有赢过"对照 + 8 步"（同文 L110）。(c) 唯一与融合一致、可部署的形式：**在融合上下文中再编码**（候选 B）。
- 建议给 v387 加一条判读：K0 ≥ +3 **且** R8 ≥ +1 才是"编码器瓶颈"；K0 ≥ +3 且 R8 ≤ 0 = 融合折中，不是可攻的瓶颈；并报告 own@R8（`final-val.json` 的 `own_wall_f1`，L626）。

**(2) 邻域上下文。** 能买到的不是"墙的连续性"（解码器在 8×8 格上已有 ≥ ±2 块感受野：L189 两层 3×3，再 L64-70），而是**上下文相关的词汇**：同一 8-bit 符号在不同邻块下表示不同图案。会破坏什么：O1 局部性（energy_restriction_gbp.md §2(c)）；max 融合不再是同态——D4-10 的 ≤ 0.4 pp 是对**块局部**编码器测的；赢家按覆盖率成片但每个 agent 只观测 19.4 块（D4-5），马赛克边界比例高。q 必须保持块局部（否则 join 由上下文而非块内证据决定）。最强反证是 dense 臂（全图上下文）：K0 .859 / R8 .707 vs owned .910 / .848（OVERNIGHT L25-26），但它没有空间所有权，不是干净的"owned + 邻域"测试。

**(3) 精度语义。** 可声明的"更有原则"版本：q_k = 校准的逆期望渲染误差 × 覆盖指示，用异方差 NLL（½·q·err² − ½·log q）校准，"自一致性"只需一次解码器前向（0.73 ms，BRIEF 第 39 行），不夹带几何，join 选"渲染最可靠的来源"。但：选择收益上限 ≈ 0.4 pp（D4-10）；去掉内容的代价 ≈ cov 臂的 −4.7 pp（N2-1）。**结论：q 没有"更有信息"的余地，"更纯"要付 ~5 pp，这是用户的语义决策而不是实验。** 零代价探针：对保存面板（L631-634 存 q、own）回归 q ~（覆盖率，块内墙像素数，墙位置）；若墙内容在覆盖率之外显著预测 q，则 q 在夹带几何，协议里应如实声明为"第二内容标量"。

**(4) 其他编码器侧（均 < +3）。** (i) 公共尺度 L 平面：解码器不知 L（BRIEF 第 50 行），编码器输入只有 xy（L100-102）；【推测】≤ +1 pp，零成本可并入任何批次。(ii) 16-bit μ 的**训练**臂（`--wire kbit --mu-bits 16`，L112、L444 已支持）：D4-11 只在弱协议下测过，但 §1.2 的 k-bit 曲线与熵使先验不利；先做 CPU 探针"v384 连续 μ 解码 vs hard-8"（跳过 L244 的 round），≥ +1 pp 才值一个租约。(iii) 1-px 平移码碰撞测试（encoder_information.md E4）判定 jitter 在编码器还是解码器——是探针，不是候选。

## 4. 反证

对 top-1 A，最可能的失败：K0 +2、R8 0——上下文在 K0 买到词汇、在 R8 被马赛克抹平，`--oracle-union` 差从 .4 升到 2–3 pp。相悖的已有结果：dense 臂（L25-26）；D4-10 的无损正是块局部性的产物；D3-4(b) 显示解码器已用邻块补回 .887 recall，即上下文的大头已在解码器一侧。
对 B：v342 的 K0 上下文精修 R8 −1.3；README §6 L202-204 的"L 计算 / 禁止后验当新观测"需审查裁定它属于哪一类。

## 5. 排序

- **top-1：A**——唯一具备 ≥ 3 pp 机制（上下文倍增每块词汇量，直指 8+ 室层）的编码器侧改动，零 FLOPs 代价，自带杀手测试（oracle-union）。
- **top-2：B**——零训练可测、与 v387 同一批读数；收益封顶于 own-drop。
- **明确不推荐**：K0 上下文的部署级测试时精修（R8 −1.2…−1.3）；用精修码训练解码器 / 半摊销（v233、v265 0/2）；为准确率改 q（上限 .4、代价 5）；8→16 bit 不经探针直接上租约；编码器加宽（"更多同类"）。
- **最重要的告诫：凡依赖上下文的编码器增益都在 K0 结算、在 R8 被马赛克征税；预注册必须含 `--oracle-union`。v387 的 K0 列单独不能判"编码器瓶颈"。**
