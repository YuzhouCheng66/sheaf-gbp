### 3. 训练器（`train_3d_v420.py`）

## 结论

**LAUNCH OK WITH CHANGES（M1、M2、M3）。**

代码的主体是对的。坐标平移与 v371 逐顶点一致，房间框方向、`[y, x] → [x, y]` 转置、楼板 / 天花 / 过梁层都经实测核对；传感器首击精确，一格厚的轴对齐墙和板在 0.0625–0.2 m 的水平格上都不漏，墙栅格里没有只靠角点相接的漏洞，65,536 束带来的孔隙可以忽略（×4 束只多 0.6–1.6 % 已知）。训练器的各向异性 space-to-depth、体素级块局部性、三处块序、2 × 2 × 2 读出、`CHART_M` 接线、指标语义（含 v401 M1 的 tol1）都已核对；本地 4080 上一次 N = 8 的完整更新 0.306 s、3.26 GiB，推算到 5090 约 0.1 s/update，会跑满 16,000 次更新。训练器、缓存生成器和链脚本在 uk-linux CPU 上端到端跑通，键、`rate()`、租约 JSON 与分析块逐项对上。

三处必改：M1 最重要。在同一判据面板上，完全不复原家具的神谕得 R8 表面 .890、可变结构 .798，现行阈值检验不到"带家具"这个结论的核心，必须在发射前加一条家具判据（推荐家具区 F1，只改训练器），并把参照写进预注册。M2 是一行 shell 的历史保护缺陷。M3 是生成器的三个小缺陷（圆柱回退、连通性参照、贴墙），每个修复都是一到几行，重做缓存约 66 分钟，可以在 RS-A 结束之前完成，不会推迟发射；如果不修，就必须披露实测比例。
