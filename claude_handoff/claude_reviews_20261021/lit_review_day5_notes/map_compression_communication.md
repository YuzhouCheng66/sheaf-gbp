# Communication-efficient map sharing and map compression for multi-robot mapping and exploration (literature to 2026)

*Scope note.* Five strands were covered: (1) classical grid/octree compression, (2) learned compression of grids and map latents, (3) neural-implicit and collaborative-SLAM systems with reported bandwidth, (4) communication-aware exploration that shares summaries instead of raw grids, (5) the reported numbers. Every byte figure below is given together with the map resolution (when the source states it) and the quality metric the source reports. "Verified" = read from the primary paper (arXiv HTML/ar5iv, publisher page, or PDF text extracted from the primary PDF). "Inference" = my own arithmetic or interpretation, flagged as such.

*Our comparison point (stated by the task, not a literature result).* Each agent's map = 64 scalars + 64 precisions at 8 bit = 128 B raw; entropy-coded to 14.1 B per self message with an occupancy-mask context coder on a synthetic family, 27.2 B on the fixed 8+8-bit wire. A lossless adaptive-context coder of the same single-agent target map needs ~300–360 bits (38–45 B); the whole-house wall map 200–430 bits. Our code is below the lossless bound of the union map because it is lossy (wall F1 0.90–0.94) and relies on a learned decoder prior. 8–16 agents, 8 rounds, diff-coded flooding totals ~60 KB per scene.

## Key question 1 — Best reported bits-per-cell / bytes-per-map for occupancy grids at a given quality (lossless and lossy)

### Takeaway
No paper in the surveyed literature reports a lossless entropy-coded bits-per-cell figure for 2D robot occupancy grids with a reconstruction metric; the closest hard numbers are OctoMap's 2-bits-per-child maximum-likelihood octree files (3D, lossy in probability only, 0.05–0.8 m), a learned binary-map codec reaching 0.007–0.008 bits/pixel on 5 cm LiDAR intensity maps (quality measured as localization error, not IoU), and quadtree-abstraction schemes that send 1.6–2.3 % of the full-map bits for planning tasks (quality measured as planning cost). None reports IoU/F1/PSNR against bytes for 2D occupancy grids, so our 14–27 B lossy code with wall F1 0.90–0.94 has no directly comparable published point.

### Cited Findings

**Classical octree/quadtree and file-level compression**

- OctoMap (Hornung, Wurm, Bennewitz, Stachniss, Burgard; *Autonomous Robots*, 2013): in-memory octree cost on 32-bit is `mem_tree = n_inner × 40 B + n_leafs × 8 B`; the maximum-likelihood binary serialization stores "16 bits of memory, 2 bits per child" per inner node (00 unknown, 01 occupied, 10 free, 11 inner), and "file sizes never exceeded 15 MB even for large outdoor environments at a fine resolution" — [Hornung et al. 2013 preprint PDF](https://www.hrl.uni-bonn.de/papers/hornung13auro-preprint.pdf) (DOI 10.1007/s10514-012-9321-0).
- OctoMap Table 2 (same source), memory in MB for "3D grid / octree none / pruned / max-likelihood" and file size "full probabilistic / lossy binary":
  - FR-079 corridor (43.7×18.2×3.3 m), 5 cm: 78.88 / 73.55 / 41.62 / 24.72; files 15.76 / **0.67 MB**. 10 cm: 10.01 / 10.87 / 7.22 / 5.02; files 2.70 / 0.14.
  - Freiburg campus (292×167×28 m), 10 cm: 5162.90 / 1257.57 / 990.66 / 504.76; files 379.70 / **13.82**. 20 cm: 648.52 / 187.93 / 130.24 / 74.12; files 49.68 / **2.00**. 80 cm: 10.58 / 4.55 / 4.12 / 3.09; files 1.53 / 0.08.
  - New College (250×161×33 m), 10 cm: 5058.76 / 607.92 / 395.42 / 230.33; files 148.75 / 6.40. 20 cm: 633.64 / 91.33 / 50.57 / 35.95; files 18.65 / 0.99. 80 cm: 10.13 / 2.34 / 1.79 / 1.69; files 0.63 / 0.05.
  - freiburg1_360 RGB-D (7.9×7.3×4.6 m, voxels carry colour), 2 cm: 252.99 / 159.97 / 45.52 / 20.05; files 21.59 / 0.52; 5 cm: 16.19 / 11.24 / 4.55 / 2.52; files 2.11 / 0.07.
  - Quality metric: the "lossy" file keeps only the thresholded occupied/free state ("loss of information close to P(n)=0 and P(n)=1"); no IoU is reported; the paper notes "map files can be compressed even further by using standard file compression methods" — [Hornung et al. 2013](https://www.hrl.uni-bonn.de/papers/hornung13auro-preprint.pdf).
- Team MARBLE semantic octree diffs (DARPA SubT; *Frontiers in Robotics and AI*, 2023): each voxel is coded with 7 bits (2 occupancy, 4 traversability, 1 stair presence); "eight sub-cubes of an octree child node take 6 bytes"; differential maps are queued and sent when a link exists; no byte sizes per diff are reported — [Frontiers 2023](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2023.1249586/full). The MARBLE system paper states mapping voxel size 0.15 m, 802.11 MTU 1500 B with 100 B reserved for overhead (1400 B payload), three packets in flight per link, and ~20 Mbit/s payload throughput measured over wired Ethernet (not over the mesh) — [Biggie et al., arXiv 2301.00771 (2023)](https://ar5iv.labs.arxiv.org/html/2301.00771).
- Grid-map transmission study for vehicles (Dehler, Authaler, Thakur, Wodtko, Buchholz; arXiv 2604.01753, Apr 2026, no venue): maps average ~350 000 cells at 10/20/40 cm; raw representation 8 B/cell (32-bit floats), quantized 2 B/cell; RLE, RLE+LZ4, LZ4, Zstd and PNG are compared patch-wise; compressed sizes appear only in figure axes (~0–70 kB for Zstd), end-to-end times at 10 Mbps: LZ4 179.2 ms, Zstd 120.1 ms, quantized LZ4 82.3 ms, quantized Zstd 48.8 ms — [arXiv 2604.01753](https://arxiv.org/html/2604.01753).
- Communication-aware hierarchical (quadtree) compression of time-varying grids (Larsson & Maity; arXiv 2504.10751, Apr 2025, no venue): compresses the "map innovation" vs the receiver's estimate with a leaf-node budget per step; 128×128 grid, budgets 1–40 % of finest-resolution nodes; only distortion curves, no bits reported; the motivating example assumes 8 bits/cell for a 1024×1024 grid at 30 fps — [arXiv 2504.10751](https://arxiv.org/html/2504.10751).
- Sample-based information-bottleneck quadtree compression (Jin & Larsson; arXiv 2609.27330, Sep 2026, no venue): MCTS-style anytime quadtree abstraction; 128×128 synthetic grids and a 2048×2048 real SLAM-Toolbox LiDAR map; retains "approximately 88 % of the information preserved by Q-tree search" at "about 11 %" of its computation time; no bits/bytes or IoU reported — [arXiv 2609.27330](https://arxiv.org/html/2609.27330).
- Communication-aware map compression for online path planning (Psomiadis, Maity, Tsiotras; arXiv 2309.13451, Sep 2023; venue not confirmed): two robots, 64×64 probabilistic map and 30×30 maze; transmission cost `n_θ = k_θ·n_m + n_i` with n_m = 12 bits per value and n_i = 4 bits per abstraction index, 10 abstractions; adaptive selection transmits 37.3 % (realistic map, 62.7 % reduction) and 56.4 % (maze, 43.6 % reduction) of full-resolution bits, at 26.9 % / 14.8 % longer path time vs fully-informed — [arXiv 2309.13451](https://arxiv.org/html/2309.13451).
- Iterative version (Psomiadis, Pedram, Maity, Tsiotras; arXiv 2503.10843, Mar 2025): 256×256 Mars map and 128×128 Earth map, Kalman-filter decoder; Mars: 7 692 bits transmitted (adaptive) vs 486 000 bits (fully-informed) = 1.6 %, accumulated planning cost 55.9 vs 47.3; Earth: 6 602 ± 115 vs 283 500 bits = 2.3 %, cost 19.4 ± 0.9 vs 16.7 ± 6.5 — [arXiv 2503.10843](https://arxiv.org/html/2503.10843v1).
- Rate-distortion version (Pedram, Psomiadis, Maity, Tsiotras; arXiv 2506.20579, Jun 2025): entropy-coded dithered quantization with a log-det rate, reverse water-filling; 128×128 / 256×256 maps; bit values are only plotted, not tabulated — [arXiv 2506.20579](https://arxiv.org/html/2506.20579v1).
- Occupancy-grid synchronization with Hilbert-curve voxel ordering (Shi, Yin, Kong, Ren, Zhu, Tang, Zhang; IROS 2024, pp. 8489–8496, DOI 10.1109/IROS58592.2024.10802281): ordering local OGMs along a Hilbert space-filling curve "increases data redundancy and lowers information entropy", reducing "average and maximum bandwidth usage by more than 10 times in high-resolution scenarios" vs a benchmark, demonstrated on multi-UAV navigation; the resolution and absolute bandwidth are not in the abstract (full text paywalled) — [OpenAlex record](https://api.openalex.org/works?search=Real-time%20Bandwidth-efficient%20Occupancy%20Grid%20Map%20Synchronization%20for%20Multi-Robot%20Systems&per_page=3); [HKU record](https://hub.hku.hk/handle/10722/354023).
- Vector maps vs occupancy grid (2016): "39.2 KB in average for a 80x80m terrain" for a vector map vs "2532.4 KB in average" for a Karto occupancy grid; grid encoding and resolution are not given in the snippet — [ResearchGate: Vector Maps (2016)](https://www.researchgate.net/publication/305804235_Vector_Maps_A_Lightweight_and_Accurate_Map_Format_for_Multi-robot_Systems).

**Learned compression**

- Learning to Localize Through Compressed Binary Maps (Wei, Bârsan, Wang, Martinez, Urtasun; arXiv 2012.10942, Dec 2020; venue not stated on arXiv — believed CVPR 2019, unverified): fully-convolutional binarizer + Huffman + run-length coding, trained end-to-end with a localizer; dense LiDAR intensity maps at 5 cm/pixel. Urban: lossless PNG 4.94 bits/pixel (median error 3.09 cm), WebP-5 0.30 bpp (6.53 cm), learned 8× 0.0083 bpp (3.47 cm, end-failure 1.22 %), learned 16× 0.00733 bpp (3.84 cm); highway: PNG 4.94 bpp (7.06 cm) vs learned 0.007 bpp (7.19 cm) — [arXiv 2012.10942](https://arxiv.org/html/2012.10942).
- D2M2N (Ishat-E-Rabban & Tokekar; arXiv 2310.07070 v2, Apr 2024; venue unknown): each robot keeps an H×1 embedding of its occupancy belief (H ∈ {16, 32, 64, 128}); grids 12×12 to 24×24 cells, no physical resolution; reconstruction accuracy (% cells correct, sizes 12/16/20/24): H=16: 97.8/96.9/93.3/90.1; H=32: 99.2/98.8/97.7/95.8; H=64: 99.8/99.6/99.2/98.4; H=128: 99.9/99.9/99.8/99.4; the paper quotes "compression ratio of 36" for 24×24 → 16 values; bytes are not stated — [arXiv 2310.07070](https://arxiv.org/html/2310.07070v2).
- MCOP, multi-UAV collaborative occupancy prediction (Lin et al.; ICCV 2025; arXiv 2510.12679): shares compressed 2D BEV features only where a request mask overlaps; 0.23 MB per transmission vs 17.50 MB (BEVDet + Where2comm) and 19.14 MB (PanoOcc + Where2comm); uncompressed 3D occupancy features 76.56 MB; mIoU 46.41 vs 41.96 (Air-to-Pred-Occ), voxels 0.4 m over 100×100 m, 4–5 UAVs — [arXiv 2510.12679](https://arxiv.org/html/2510.12679).
- Where2comm (Hu et al.; NeurIPS 2022): communication volume defined as log2(|M|·D·32/8) bytes, counting only non-zero BEV cells × channels at float32 with "no extra data/feature/model compression"; OPV2V (0.5 m/pixel BEV): 5.67 log2-bytes at AP@0.5 40.11 vs DiscoNet 22.28 log2-bytes at 36.00; V2X-Sim (0.4 m/pixel): 6.70 at AP 47.60 vs 20.00 at 58–59; fusion is per-location multi-head attention across agents — [ar5iv 2209.12836](https://ar5iv.labs.arxiv.org/html/2209.12836).
- No paper applying VQ-VAE / "neural map compression" to robot occupancy grids with a bits-vs-IoU curve was found; VQ-VAE semantic-communication work (arXiv 2301.05901, 2401.16236) compresses observations for remote control, not maps — [search summary via arXiv 2301.05901](https://arxiv.org/pdf/2301.05901).

### Inferences
- OctoMap lossy binary files, expressed per bounding-box cell (my arithmetic from Table 2): Freiburg campus 20 cm → 292×167×28 m / (0.2 m)³ ≈ 1.71×10⁸ cells, 2.00 MB ≈ 1.68×10⁷ bits → ≈ 0.10 bit/cell; FR-079 5 cm → ≈ 2.1×10⁷ cells, 0.67 MB → ≈ 0.27 bit/cell; Freiburg campus 10 cm → ≈ 1.37×10⁹ cells, 13.82 MB → ≈ 0.085 bit/cell. These are tri-state (occupied/free/unknown) with unknown implicit, before any entropy coding, and the ratio lossy-file : dense float grid is 118× (FR-079, 5 cm) to 374× (Freiburg campus, 10 cm).
- Wei et al.'s 0.007–0.008 bpp is the lowest bits-per-cell figure found for any 2D robot map, but the decoder target is localization, not grid reconstruction, so it cannot be converted to IoU/F1.
- D2M2N at float32 (inference; the paper never states the dtype): H=16 → 64 B per robot message, H=32 → 128 B, H=64 → 256 B, H=128 → 512 B; on the 24×24 grid that is 0.89 bit/cell at 90.1 % cell accuracy (H=16) and 7.1 bit/cell at 99.4 % (H=128); on the 12×12 grid H=16 is 3.6 bit/cell at 97.8 %. Our 128 B raw / 14.1 B coded per agent is in the same raw-size class as D2M2N H=32 but with an explicit precision channel and entropy coding, which D2M2N lacks.
- Psomiadis-family per-step payloads (my arithmetic from the stated formula): a 7×7 field of view at full resolution costs 49 × 12 = 588 bits (73.5 B); a k=7 abstraction costs 7×12 + 4 = 88 bits ≈ 11 B (12-bit values) or 7×24 + 4 = 172 bits ≈ 21.5 B (mean+variance, 24-bit); in the iterative paper 7 692 bits over a 180-step horizon ≈ 43 bits ≈ 5.3 B per step. These are the only published per-update map payloads in the 5–25 B range, and their quality metric is planning cost, not map F1.
- Where2comm's lowest OPV2V budget 2^5.67 ≈ 51 B per message (my arithmetic) at AP@0.5 40.11 shows that sparse feature selection can push a per-agent message to tens of bytes, but for object detection on a 0.5 m BEV, not for map reconstruction.
- For lossless coding of 2D occupancy grids, the literature offers only generic codecs (PNG, LZ4, Zstd, RLE) without bits-per-cell tables; our 300–360-bit adaptive-context bound for a single-agent target map and 200–430 bits for the whole-house wall map therefore cannot be checked against a published number and should be presented as our own measurement.

### Gaps
- No source found that reports lossless entropy-coded bits-per-cell (JBIG2/context-arithmetic coding) for 2D occupancy grids; the vehicle grid-map study (arXiv 2604.01753) compares RLE/LZ4/Zstd/PNG but gives sizes only in figures.
- No 2D occupancy-grid paper reports IoU/F1/PSNR as a function of bytes; quality is reported as planning cost (Psomiadis family), localization error (Wei et al.), cell accuracy on toy grids (D2M2N), or not at all (OctoMap).
- The IROS 2024 Hilbert-curve synchronization paper's absolute bandwidth, codec and voxel size are behind the IEEE paywall; only the ">10×" claim is verifiable from the abstract.
- The "Resilient Multi-UAV Collaborative Mapping" paper (*Drones* 2026, DOI 10.3390/drones10040242, "prefix-decodable streaming" submaps) returned HTTP 403 on both MDPI and DOI routes; its byte figures are unknown.

## Key question 2 — Which works quantise a map or map-latent to a fixed small budget (≤ hundreds of bytes) per robot per update, and what accuracy do they keep?

### Takeaway
Only a handful of works operate at hundreds of bytes or less per robot per update: a DRL exploration policy with a fixed 256 B (64 × float32) message (99.2 % communication saving, +2.4 % travel distance), D2M2N's 16–128-float embeddings (90–99.9 % cell accuracy on ≤24×24 toy grids), Psomiadis-style abstraction codes (≈11–22 B per 7×7 patch, 1.6–2.3 % of full-map bits at modestly higher planning cost), position-only sharing at 13 B per message, and Where2comm's confidence-selected features (~51 B at AP 40). None of these entropy-codes a learned map latent with a precision channel, and none reports wall/obstacle F1 at those budgets.

### Cited Findings
- Privileged Reinforcement and Communication Learning for bandwidth-limited exploration (Ma, Liang, Cao, Tan, Sartoretti; arXiv 2407.20203, Jul 2024; arXiv lists "Accepted by DARS 2024"): "each message packet is a 1x64-dimensional float32 tensor (i.e., 64×4 bytes)", a 256 B cap per message; baselines send H×W int8 belief maps; 100 m × 100 m dungeon maps (grid resolution not stated), 4 robots (8 at test without retraining); worst-robot results at 95 % coverage: upload 5.7 MB vs 656.2 MB (mTSP baseline) / 679.2 MB (global-map), download 17.2 MB vs 1 791.1 / 2 037.7 MB, travel distance 205.7 vs 200.8 (+2.4 %); 8 robots: upload 4.5 MB, download 32.0 MB vs 516.6–554.7 / 3 303.1–3 616.4 MB — [arXiv 2407.20203](https://arxiv.org/html/2407.20203); venue note from [search listing](https://arxiv.org/abs/2407.20203v1).
- D2M2N (arXiv 2310.07070): fixed H-dimensional embedding per robot, shared with neighbours within Manhattan range 8, merged by an MLP message aggregator "one by one"; navigation success (ASA) 97 % / SPL 0.97 on simple 12×12, 82 % / 0.57 on complex 24×24 with H=32; reconstruction accuracies as listed under KQ1 — [arXiv 2310.07070](https://arxiv.org/html/2310.07070v2).
- Psomiadis et al. 2023 / 2025 abstraction codes: fixed codebook of 10–16 abstraction templates, 4-bit template index plus k values at 12 bits (or 24 bits with variance), decoded by a convex QP or Kalman filter; 1.6–2.3 % of fully-informed bits with planning cost 55.9 vs 47.3 (Mars) and 19.4 vs 16.7 (Earth) — [arXiv 2309.13451](https://arxiv.org/html/2309.13451); [arXiv 2503.10843](https://arxiv.org/html/2503.10843v1); multi-sensor variant with mean+variance triplets (o, V, θ), 1 actor + 3 sensors on a 64×64 grid, bit ratios 0.78–1.0 and ~70 % task-cost reduction vs uninformed — [arXiv 2403.14780](https://arxiv.org/html/2403.14780).
- Bayer & Faigl, Decentralized multi-robot exploration under low-bandwidth communications (*Autonomous Robots* 50:7, published 29 Dec 2025): position message = 13 B (three floats + 1 B id), 5 Hz → 65 B/s per robot; LoRa-class 868/915 MHz radios allow "about 100 B/s" per robot; map sharing in their simulations averaged 23.5 kB/s (≈235× the budget), waypoint sharing ≈66 B/s; an NDT map-sharing method is cited at 37.5 kB/s (≥4.1 kB/s); teams of 3/5/7/9 in simulation, 3 Spot quadrupeds at 1 Hz in the field with ~75 % packet loss; position-only methods CRESR^p/CRTSP^p "fulfill the bandwidth requirements" while the best-ranked map-sharing planners (MTSP/MinPos/Hun) do not — [Springer article](https://link.springer.com/article/10.1007/s10514-025-10234-3).
- Where2comm (NeurIPS 2022): per-message volume down to 2^5.67 bytes on OPV2V at AP@0.5 40.11 (vs 2^22.28 bytes at AP 36.00 for DiscoNet), definition and fusion as in KQ1 — [ar5iv 2209.12836](https://ar5iv.labs.arxiv.org/html/2209.12836).
- MR-GMMExplore (Wu, Gu, Yu, Ge, Wang, Liao, Zhang, Wang; Tsinghua; venue not stated in the preprint): a GMM submap of 80 components averages 4 138 B vs 95 836 B for the point-cloud submap (20 frames, ≈0.6 s per frame) — "approximately 96 % communication load" saved; exploration grid for planning l = 1 m; builds on MR-GMMapping (RA-L vol. 7 no. 2, pp. 3294–3301, 2022); the paper also cites Tabib et al. for "approximately 200× that of occupancy grid maps (from 1 MB/s to 5 KB/s)" — [MR-GMMExplore PDF](https://nicsefc.ee.tsinghua.edu.cn/nics_file/pdf/3f18206c-0703-4ad6-9e46-1d61efbca467.pdf).
- MR-TopoMap (Zhang, Yu, Tang, Xu, Wang; RA-L, accepted June 2022): per two-robot exploration run, small environment: ScanPerSubmap 493 KB (PR 56.3 + RelPose 79.2 + Submap 357.5), ScanPerMatch 434 KB, OnlySubmap (PNG submaps, SMMR) 357.5 KB, TopologicalMap 77.3 KB (PR 64 + Position&UD 7.5 + ID&Edge 3.3); large environment: 1 403.7 / 1 308.9 / 990 / 135.3 KB (PR 112 + Pos&UD 13.1 + ID&Edge 10.2); "data transfer is reduced by 84 %∼90 %"; exploration coverage 99.1–99.5 % (small) and 95.2–95.6 % (large) vs 98.5–99.8 % for RRT/MMPF; the paper also states the occupancy grid accounts for "around 70 % of all traffic" in typical DSLAM systems — [MR-TopoMap PDF](https://nicsefc.ee.tsinghua.edu.cn/nics_file/pdf/8ac5aaef-72e5-4d5b-ad39-5adb4cad8d91.pdf).
- MEF-Explore (IEEE T-ASE 2025, DOI 10.1109/TASE.2025.3575237; arXiv 2505.23376): positions over "ever-ready low-speed communication" (UWB LinkTrack in hardware), maps only over high-speed WiFi within r_comm = 4 m; GMapping grids at 0.05 m; 2–5 robots in simulation, 10/15 in scalability tests, 3 TurtleBot2 in a 223 m² room; 11.6–46.4 % faster exploration than MWF-CN/MMPF; no byte figures — [arXiv 2505.23376](https://arxiv.org/html/2505.23376).

### Inferences
- Ranking of published per-robot-per-update map payloads (all my unit conversions): position-only 13 B (Bayer & Faigl) < Psomiadis abstraction ≈ 11–22 B per 7×7 patch < Where2comm ≈ 51 B (OPV2V low budget) < D2M2N 64–512 B (float32 assumed) < Ma et al. 256 B fixed < MR-GMMExplore 4.1 KB per submap < MR-TopoMap ~77–135 KB per run. Our 14.1 B (coded) / 27.2 B (fixed wire) / 128 B (raw) per agent sits at the low end of this list while carrying a decodable full map with precisions, which none of the sub-100 B entries do.
- Accuracy at those budgets is reported in heterogeneous units: cell accuracy 90–99.9 % (D2M2N, toy grids), planning-cost ratios (Psomiadis), AP (Where2comm), exploration time (position-only schemes). Our wall F1 0.90–0.94 would be the first obstacle-F1-vs-bytes point for a learned map code if reported as such.
- The dominant strategy for ≤100 B budgets in the exploration literature is to stop sending maps at all (positions, waypoints, topological vertices); learned fixed-size latents (D2M2N, Ma et al.) are the only ones that still let a receiver recover spatial map content.

### Gaps
- D2M2N does not state the embedding dtype or any byte count, and its venue is unknown (arXiv only, v2 Apr 2024).
- Ma et al. report map resolution only as 100 m × 100 m maps; the H×W of the int8 baseline belief maps is not given, so their 99.2 % saving cannot be converted to bits/cell.
- MR-TopoMap does not state the grid resolution of the PNG submaps in Table IV (not captured in the extracted text), nor does MR-GMMExplore state the point-cloud voxel size.

## Key question 3 — How multi-robot SLAM systems account communication (bytes, headers, retransmissions) and typical mission totals

### Takeaway
Collaborative-SLAM papers almost always report application-layer payload totals in kB/MB per module (place recognition, geometric verification, back-end), measured by summing message sizes; only the Kimera-Multi 2023 field paper reports transport-level statistics (ENet bandwidth per robot pair, delay, packet drop 20–46 %), and none itemises headers or retransmissions. Typical totals: 24–146 MB per team for Kimera-Multi (3–5 robots, 1.7–5.1 k poses), 94.95 MB for Swarm-SLAM (3 robots, 475 m, 3 103 keyframes), ~25–29 MB for a two-agent neural-implicit SLAM (MCN-SLAM), 0.4–1.8 GB per agent for distributed NeRF training, versus 5.7 + 17.2 MB for a 4-robot DRL exploration run with 256 B messages — all orders of magnitude above our ~60 KB per scene for 8–16 agents × 8 rounds.

### Cited Findings

**Feature-based collaborative SLAM**

- Kimera-Multi (Tian, Chang, Herrera Arias, Nieto-Granda, How, Carlone; IEEE T-RO 2022; arXiv 2106.14386), Table II total data transmitted (MB) as PR / GV / DPGO / total vs centralized (images) / centralized (keypoints): Medfield (3 robots, 2 918 poses) 22.6 / 41.5 / 1.8 / 65.9 vs 2 113 / 141; City (3, 3 212 poses) 16.2 / 44.5 / 8.8 / 69.5 vs 2 326 / 155; Camp (3, 5 088) 39.2 / 19.7 / 0.5 / 59.4 vs 3 685 / 246; Vicon Room 1 (3, 1 693) 9.5 / 14.7 / 3.6 / 27.8 vs 1 226 / 81.7; Vicon Room 2 (3, 1 738) 11.5 / 10.2 / 2.7 / 24.4 vs 1 259 / 83.9; Machine Hall (5, 3 261) 46.0 / 76.8 / 22.9 / 145.7 vs 2 362 / 157; PR = DBoW2 bag-of-words vectors, GV = keypoints + descriptors; the paper does not say whether totals are per robot or per team, nor whether headers are counted — [ar5iv 2106.14386](https://ar5iv.labs.arxiv.org/html/2106.14386).

- DOOR-SLAM (Lajoie, Ramtoula, Chang, Carlone, Beltrame; RA-L vol. 5 no. 2, pp. 1656–1663, 2020), Table II average message sizes "computed during our field experiments" (two quadrotors, Jetson TX2 over WiFi): NetVLAD descriptor (first 128 dims kept) 1.00 kB per keyframe; keypoints 34.51 ± 0.68 kB and descriptors 25.00 ± 0.49 kB per matched keyframe; RGB image 900.04 kB; grayscale 600.06 kB; inter-robot pose estimate 0.34 kB; loop-closure measurement 0.34 kB; the front-end reduces bandwidth "by roughly a factor of 10" vs images; subterranean back-end (DARPA Tunnel Circuit lidar): 92.27 kB distributed vs 196.30 kB centralized — [arXiv 1909.12198](https://arxiv.org/html/1909.12198v1).

### Inferences
- Accounting convention: every C-SLAM paper above counts serialized application payloads (descriptor/keypoint/pose message sizes summed over the run); none adds IP/UDP/802.11 headers, ROS/DDS framing, or retransmissions. The only header-aware statement is MARBLE's 100 B of 1500 B reserved per packet (≈6.7 % overhead), and the only transport-level measurement is Kimera-Multi 2023's ENet bandwidth/packet-drop table. Our "fixed 8+8-bit wire" (27.2 B) and diff-coded flooding total (~60 KB per scene) should therefore be labelled as payload-only to be comparable, and a per-message header budget (≥ 20–60 B for UDP/IP, more for DDS) will dominate a 14–27 B payload — worth stating explicitly.
- Per-keyframe costs scale the totals: Swarm-SLAM's 94.95 MB / 3 103 keyframes ≈ 30.6 kB per keyframe (my arithmetic); Kimera-Multi Medfield 65.9 MB / 2 918 poses ≈ 22.6 kB per pose; DCL-SLAM 29.12 kB per LiDAR frame for the descriptor alone. A 128 B raw map per agent per round is ~200× smaller than one keyframe descriptor exchange.
- Neural-implicit systems trade images for weights but remain MB-scale per update (1.5–13 MB per frame/iteration), i.e. 10⁴–10⁵× our per-agent code; this is the regime where "map-to-latent" consensus (DiNNO/MACIM/RAMEN) currently lives.

### Gaps
- Whether Kimera-Multi's Table II totals are per robot or team-wide is not stated; the measurement method (payload vs serialized message size) is not stated in either Kimera-Multi paper.
- DCL-SLAM's per-frame numbers come from a search summary of the arXiv paper and were not verified against its table.
- LAMP 2.0, Di-NeRF, RAMEN and MACIM (own paper) report no byte counts at all.
- The "Multi-agent collaborative incremental implicit mapping based on topological communication protocol" paper (*Complex & Intelligent Systems* 2025, DOI 10.1007/s40747-025-02214-y) could not be fetched (Springer cookie wall); its communication-volume claims vs MACIM/Di-NeRF are unknown.

## Key question 4 — Is there prior work with a per-robot map code of fixed dimension (e.g., 64–256 numbers) that other robots can decode and that composes across robots?

### Takeaway
The closest precedents are D2M2N (a fixed H=16–128 vector per robot, decodable to its occupancy grid and composed with neighbours' vectors through a learned MLP aggregator) and the DiNNO/MACIM/RAMEN family (whole network-weight vectors composed by consensus averaging, MB-scale); learned-message exploration (Ma et al., 64 floats) and Where2comm features are fixed-size but not decodable into a map, and the Psomiadis abstractions are decodable but template-indexed rather than fixed-dimension. No published work combines a fixed 64-dimensional map code with explicit per-dimension precisions, entropy coding to tens of bytes, and additive composition across robots.

### Cited Findings
- D2M2N: "each robot maintains an H×1 embedding" of its belief map; neighbours' embeddings are merged by an MLP message aggregator "one by one" into the receiver's intermediate embedding; a decoder reconstructs the grid (accuracy table under KQ1); H = 32 is used for navigation, 4 robots default (1–6 tested), communication range 8 cells — [arXiv 2310.07070](https://arxiv.org/html/2310.07070v2).
- Ma et al. (DARS 2024): fixed 1×64 float32 learned message per robot per step, consumed by the policy (attention over received messages), not decoded into a map; results under KQ2 — [arXiv 2407.20203](https://arxiv.org/html/2407.20203).
- Where2comm (NeurIPS 2022): per-agent sparse BEV feature packets of variable cell count × D channels, fused by per-location multi-head attention weighted by the sender's confidence map; the ego feature is always included; no explicit map decode — [ar5iv 2209.12836](https://ar5iv.labs.arxiv.org/html/2209.12836).
- MCOP (ICCV 2025): compressed 2D BEV features shared only in requested regions, 0.23 MB per transmission, fused for collaborative 3D occupancy prediction (mIoU 46.41) — [arXiv 2510.12679](https://arxiv.org/html/2510.12679).
- DiNNO-family neural-implicit consensus: MACIM has each agent train "on local data plus its peers' network weights" and share updated weights so "all local networks stay consistent" — [BIT record](https://pure.bit.edu.cn/en/publications/macim-multi-agent-collaborative-implicit-mapping/); RAMEN exchanges feature-grid parameters Θ and uncertainties u and performs uncertainty-weighted consensus ADMM — [arXiv 2502.19592](https://arxiv.org/html/2502.19592v1); Distributed NeRF Learning shares full model weights with two neighbours at 13.169 MB per iteration — [arXiv 2409.20289](https://arxiv.org/html/2409.20289); OpenMulti agents "exclusively exchange NeRF network parameters" for a parameter-consistency loss, plus poses and downsampled instance point clouds — [arXiv 2509.01228](https://arxiv.org/html/2509.01228).
- Psomiadis abstraction codes: a shared codebook of 10–16 templates; message = template index (4 bits) + k averaged values; the receiver decodes by convex optimization; with 3 sensors the actor fuses all received abstractions (Scenario 1, 64×64 grid) — [arXiv 2403.14780](https://arxiv.org/html/2403.14780); [arXiv 2309.13451](https://arxiv.org/html/2309.13451).
- MR-GMMExplore: a submap is a fixed count of 80 Gaussian components (~4 138 B), composable by union across robots, decodable to occupancy at arbitrary resolution — [MR-GMMExplore PDF](https://nicsefc.ee.tsinghua.edu.cn/nics_file/pdf/3f18206c-0703-4ad6-9e46-1d61efbca467.pdf).
- MR-TopoMap: per-vertex message = ID + place-recognition descriptor + position + unexplored directions + edges; vertices compose into a shared topological graph by descriptor matching (threshold 0.75) — [PDF](https://nicsefc.ee.tsinghua.edu.cn/nics_file/pdf/8ac5aaef-72e5-4d5b-ad39-5adb4cad8d91.pdf).

### Inferences
- D2M2N is the only prior work found whose per-robot code is (a) fixed-dimensional in the 16–128 range, (b) decodable to a grid by any robot, and (c) composed across robots — but composition is a learned, order-dependent MLP (no closed-form or additive rule), there is no precision/uncertainty channel, no quantization or entropy coding, and evaluation is on ≤24×24 synthetic grids with no physical resolution. Our 64-scalar + 64-precision code with entropy coding and diff-coded flooding is therefore novel on the precision channel, the coding, and the scale, while D2M2N is the correct prior to cite for "fixed map latent shared and merged among robots".
- The uncertainty-weighted consensus in RAMEN (per-parameter uncertainty u shared with Θ) is the closest analogue to our "scalars + precisions" pairing, but at the full-network scale (MB per exchange) rather than 64 numbers.
- Where2comm/MCOP show that confidence-gated sparse latents can be composed by attention at ~50 B–0.23 MB per message for perception tasks; they do not reconstruct a map, so they are an analogue for the "composes across robots" property only.

### Gaps
- No paper was found that quantizes a learned map latent to 8 bits with learned or explicit precisions and entropy-codes it with a context model; the "neural map compression" / "map-to-latent for communication" phrasing in the task did not match any 2018–2026 robotics paper in the searches run (queries: learned occupancy grid compression autoencoder; neural map compression latent VQ-VAE; deep learning occupancy grid compression IoU bitrate).
- D2M2N's composition order-dependence and scaling beyond 6 robots are untested in the paper.
- 4CNet (diffusion map prediction for decentralized exploration; arXiv 2402.17904, 2024–25) uses nearby robots' trajectories as conditioning, but whether robots share predicted maps or raw maps is not stated on the abstract page (HTML version returned 404) — [arXiv abs 2402.17904](https://arxiv.org/abs/2402.17904).
- WiSER-X (Jadhav, Behari, Wood, Gil; arXiv 2412.19876; listed as RA-L 2026 by the authors' lab page) coordinates without explicit information exchange (wireless-signal pings only), i.e. zero map bytes; its numbers were not extracted — [arXiv 2412.19876](https://arxiv.org/html/2412.19876v2).
