# Day-5 第一性原理分析：表示 / 信息几何——64 个标量（+64 精度）应当"指什么"

角色：REPRESENTATION / INFORMATION GEOMETRY（独立分析，只读）。数字全部取自 BRIEF_DAY5_FP.md、OVERNIGHT_REPORT D 节、BEST_RESULTS_20261023.md、train_v378.py、mapping_houseexpo_data_v371.py、owned_ceiling_v371.py；标"（推测）"的是我的推断，其余是引用或由引用数字直接折算。

## 0. 一句话结论
现状是"每个 8×8 公共方块一个 8-bit 标量"。真实户型的信息按块**极不均匀**：直墙块 ≈ 3–5 bit，门洞/墙端/拐角/丁字块 ≥ 9–14 bit，而每块只有 8 bit。8+ 室户型的无损需求已超过 512 bit 的均值总量，所以在 64 变量硬约束内**不存在"大幅"提升的表示**；最有把握的两个结构改动是 **按墙向分解的各向异性双网格**（top-1）和 **把标量读成 255 级符号表**（top-2），各自预期 +2–4 pp。

## 1. 第一性原理：R8 .89–.90 的残差由什么决定

**(1) 每块预算 vs 每块需求。** 贴合图幅后户型平均覆盖 45/64 块（D4-5）。把 D4-7 的无损码长（v371 行）折算到每个落在房子上的块：

| 层 | 多边形描述 bit/块 | 整栋墙图 bit/块 | 可用均值 bit/块 | VAL R8（两种子）|
|---|---|---|---|---|
| 2–4 室 | 282/45 = 6.3 | 221/45 = 4.9 | 8 | .94 / .93 |
| 5–7 室 | 516/45 = 11.5 | 308/45 = 6.8 | 8 | .93 / .92 |
| 8+ 室 | 794/45 = 17.6 | 430/45 = 9.6 | 8 | .84 / .87 |

（分层 R8：BEST_RESULTS §1 分层表。）只有 2–4 室层的需求低于 8 bit/块，F1 随"需求/预算"单调下降。8+ 室整栋多边形 794 bit > 512 bit：**即使理想码也不能在该层做到像素级**，只能靠解码器先验补——这是 64 维约束本身的上界，不是某个模块的错。

**(2) 需求是突发的，分配是均匀的。** 块边 L/8 = 1.0–2.5 m，块内 16×16 px（train_v378.py L90、L103）。按像素级需求枚举块型（我的计数）：空块/直墙贯穿（偏移可由邻块连续性推断）≈ 1–5 bit；门洞或墙端（向 1 + 偏移 4 + 开口位置 4 + 宽度 3）≈ 12 bit；拐角/丁字（两个偏移 + 两个端点 + 类型）≈ 11–14 bit。8+ 室每块平均 1.76 个多边形顶点（79/45，D4-7），即**大多数块含拐角或端点**。这与残差解剖一致：漏的是门洞两侧短墙、窄开口、大户型薄内墙（brief "Residual anatomy"；figures/houseexpo_best_v383_panels.png 第 3、6 行红色集中在内墙交汇处），自由区与外墙近乎完美。v293 能到 .94 是因为生成器只有 0.8 m 门、0.3 m 墙、矩形房间，块型集合极小（encoder_information.md §2.4）。

**(3) 8 bit 里实际用到几 bit？** v293 证据：率项 λ=0.01 把 H_μ 从 7.59 压到 4.40 bit/坐标，R8 只损 0.26 / 0.91 pp（D4-14、D4-19）；8→6 bit 直接减位的代价 0–4 pp、种子方差大（D3-12）。即 v293 上解码器真正用到的 μ 信息约 4–5 bit/坐标；HouseExpo 未测。机理（推测）：解码器读码的入口是对 8×8 栅格上 (μ, log var) 两平面做 3×3 卷积 → 64 通道 SiLU → 再一层 64（L189），然后双线性到 16×16（L200）；沿 μ 轴只有几十个"拐点"，一条平滑曲线映不出 255 个可区分图案。16 bit 上限不变（D4-11）与此一致，但见 (5)。

**(4) 融合不是残差来源，线路有隐性税。** 理想同态与实际 R8 差 ≤ 0.4 pp（D4-10）；max 选择在源头一次量化、逐位转发（L335-337），belief 再 hard-8（L346-347）。所以"坐标含义"问题全部落在"单块标量能表达什么 × 标量放在哪"。但封存 profile-4 线路把 η = pμ 编成 7-bit 块浮点，v293 上 47 % 的坐标回码后偏移 ≤ 3 级（energy_restriction_gbp.md §2(a)）——任何"用相邻级别表达不同图案"的设计都必须对此鲁棒。

**(5) 自由码上限协议低估，且偏差与布局相关。** owned_ceiling_v371.py 按默认参数用 64 索引 × 3 层 × 2 种 N = 384 个 TRAIN 场景、4,000 步、batch 64 训练解码器（L117-125），VAL 码从零起 300 步 Adam 只对自身观测拟合（L190、L270-278），并集用精度加权平均而非 max（L98-103）。主模型 K0 .92 > 协议 .819（D4-8、D5-1）说明它至少低估 10 pp，来源是解码器先验数据不足（600→7,200 户就 +5–10 pp，D4-12）和无协同训练。推论：(i) 4×4×4 < 8×8×1（.623 vs .694，D4-6）混合了"4 个耦合标量更难从零拟合"和"块更粗"，不能单独证明"每块多标量无用"；(ii) 16×16×1 的 .918 同样是下界，64 vs 256 维的真实差距未知；(iii) **"16 bit 没用"只在该协议下成立，训练系统里从未测过**（train_v378.py 已有 `--mu-bits`/`--wire kbit`，L112、L428-430、L444）。因此"卡在每块一个标量而不是 bit"是合理猜想，不是测量结果。

**(6) 三个硬要求 (a)(b)(c) 对表示的约束。** (a) 坐标必须由块局部编码器从自身 patch 算出（L86-107 的严格块局部结构正是为此）；(b) 坐标 k ↔ 公开固定物理量，否则 join 无意义——这排除一切**单阶段**自适应分配（不同 agent 的 k 指不同区域；"join 后剪枝"也不满足结合律）；(c) 薄墙 1–3 px（栅格 L/128 = 6–16 cm，保守栅格化 v371 L50-51）要求块内偏移精度 ≤ 1 px，即每条墙线至少 4 bit 偏移。

## 2. 候选结构（≤ 3）

### A（top-1）按墙向分解的各向异性双网格：64 = 32 个横墙块（4×8，L/4 宽 × L/8 高）+ 32 个竖墙块（8×4）
- **机制**：户型 100 % 轴对齐（D4-7）。一个方块的内容是（横墙构型 × 竖墙构型）的**乘积**，8 bit 只能编码最常见的联合型；把两个因子分到两个坐标后，每个坐标只需表达"一条线 + 偏移 + 端点/开口"（≈ 7–9 bit），拐角/丁字变成"横因子在 x_c 结束 + 竖因子在 y_c 结束"，各自装得下。块沿墙向加长一倍（端点位置多 1 bit），垂直墙向不变（同一横块内出现两条横墙需房间 < 2.5 m，罕见）。
- **编码器如何从部分观测算**：PatchTrunk 仍按 16×16 patch 卷积（L86-107 不变）；横块特征 = 水平相邻两 patch 的 mean/max 池化，竖块 = 垂直相邻两 patch 池化；OwnedHead 不变（L146-161）；覆盖指示改为各向异性块的 avg_pool（L155，核 (p,2p)/(2p,p)）。零额外卷积成本。
- **解码器如何读**：两组后验 (μ, log var) 分别 reshape 为 4×8 与 8×4，各双线性到 16×16，拼成 4 平面进 pre（L189 planes=4，L196 改 reshape），trunk 不变；横平面负责横线、竖平面负责竖线，交汇由 trunk 叠加。
- **约束逐条**：(1) 64 均值 + 64 精度，精度仍是"该块看到多少"的置信 ✓；(2) k ↔ 公开固定区域，max join 不变、精确 ✓；(3) 解码器只读后验 + 固定公开布局 ✓；(4) 划分不动 ✓；(5) 算力 ≈ 对照，两种子并行一个租约 ✓（需 200 步预检）；(6) ✓。
- **预期与依据**：R8 +2–4 pp，8+ 室 +3–5 pp。残差集中在拐角/端点块（§1(2)）；因子码让这些块从"≥ 11 bit 装进 8"变成"≤ 9 bit 装进 8"；代价是块面积 ×2 的马赛克/覆盖损失，可用现成 `--oracle-union`（L435）直接量。
- **对照**：批次 Q（`runs/v382-long/d4800e4-s<seed>`：从头 57,600 次更新、lr 3e-4、封存线路），同种子；同形初始张量逐位相等作身份守卫（analyze_v386 做法）。
- **预注册判据**：两种子 final VAL R8 ≥ 对照 +1.5 pp 且 8+ 室 ≥ +2 pp 且 FPR ≤ +0.3 pp 且 known acc ≥ −0.2 pp（README §7 保护规则）；两种子都 ≥ +3 pp 才标"大幅"。附报 K0、fresh、开口 free-recall、oracle-union 差（预期 ≤ 1 pp）。
- **否定证据**：oracle-union 差 ≥ 2 pp（大块马赛克主导）；K0 ≤ 对照（直墙块反而变差）；FPR/acc 守卫破；或 §3 的"块越大越差"曲线占优。

### B（top-2）把标量读成 255 级符号：解码器入口用 255 结点的分段线性查表（每级一个 64 维嵌入 + 二阶差分平滑）
- **机制**：不改码、线路、融合，只把"平滑读码"换成"逐级可分辨读码"，把（推测的）有效 4–6 bit 提到 8 bit：每块图案数 ×4–16；45 块 × 2 bit ≈ 90 bit ≈ 9 个多边形顶点 ≈ 2–4 个开口/户。
- **编码器**：不变（tanh→hard-8 STE，L154、L240-244）；STE 梯度经查表局部斜率回传。
- **解码器**：μ 平面先过 E[ℓ]，ℓ = round(127μ)+127 ∈ 0..254，再进 pre（L189 输入 64+1 平面）；二阶差分罚使相邻级图案相近，从而对封存线路 ≤ 3 级偏移鲁棒（§1(4)）。
- **约束**：全部 ✓（+16k 参数；μ 仍是一维 hard-8 量，join 不变，精度未动）。
- **预期**：+2–3 pp，以 K0 为主；对照批次 Q，判据同 A。
- **否定证据（发射前 10 分钟 CPU 可测）**：对 v384 已观测坐标做 ±1/±2/±4 级扰动，若 ±1 级就掉 K0 ≥ 1 pp，说明解码器已分辨单级、无余量 → 放弃；HouseExpo 训练内 b6 比 b8 低 ≥ 2 pp（字母表已用满）；批次 T（pre 64→128，D5-2）若 ≥ +2 pp，则机制已被宽度部分吸收，B 的增量缩小。

### C（方向，不进本轮）两阶段共识的自适应四叉树：16×16 细格上恒 64 个叶
- **机制**：先用同一 join 对每块"复杂度"（2 bit，单调 = max）达成共识，再按公共规则把复杂块一分四、把空/未观测块四合一（叶数恒 64），各 agent 按同一分配重新编码（编码 0.44 ms，可承受）。这是**唯一**能把 16×16 分辨率放到门洞处且 join 仍有意义的方式；单阶段自适应分配违反 (b)。
- **约束**：(1) 第一阶段复杂度图是不经 64+64 瓶颈的样本相关信息——与贴合图幅的 bbox 同类但更强（≈ 128 bit 侧信息），必须作为公共框架协议扩展声明并计字节；(5) 数据通路 + 协议改动，装不进一个租约。
- **预期** +1–3 pp：零和重分配，8+ 室几乎没有可合并的"简单块"，最需要的地方余量最小。首个可做的检验：用 reached 并集算出的分配（相当于共识收敛结果）训练一对，判据同 A。

## 3. 反证（针对 top-1 A）
- **最可能的失败**：块面积 ×2 的代价大于因子化收益。相悖的已有结果：同协议下 4×4×4（.623）< 8×8×1（.694）（D4-6）；固定 20 m 图幅（2.5 m 块）→ 贴合图幅（≈ 1.5 m 块）+10 pp（D4-8）；矩形图幅多 17 % 有效块 ≈ +1.4 pp（D4-17）。三者都说"单位越小越多越好"，而 A 在墙向把单位加大一倍；若残差主要由"块数/块大小"而非"块内联合型"决定，A 为负。
- **覆盖分辨率**：横块与竖块各在一个轴上粗一倍，K0 的 known 支撑要由两个"或"平面的交集重建，可能抬高 unknown-FPR（现 .011–.013）。
- **含义是涌现的**：学习到的码未必按"横/竖"分工；若不分工，A 退化为两个各向异性 8-bit 块码，收益归零（但不应大幅为负）。
- 对 B 的反证：v293 的 4.4 bit 结果可能只因 v293 块型少；HouseExpo 可能已用满 8 bit——所以 B 必须先过 CPU 扰动测试。

## 4. 排序
- **top-1：A**。唯一从"轴对齐 + 块内容是乘积"推出的分配；零额外算力；代价可用 oracle-union 直接量化；针对最弱的 8+ 室层。
- **top-2：B**。最便宜、约束最干净、有 10 分钟 CPU 预检；若预检显示 ≥ 2 bit 余量，它与 A 的收益可叠加（分别一个租约）。
- **不推荐**：(i) 4×4×4 及任何"更粗块 × 多标量"——块内容随面积超线性复杂化、联合拟合更难，上限测量也相反；(ii) Hough/Radon 式"行槽 + 列槽"——两个一维投影不唯一确定多房间图，且槽索引在部分观测下跨 agent 不一致，违反 (b)；(iii) 人工声明的乘积码（向|偏移|开口）直接写进 8 bit——拐角型装不下，封存线路 ±3 级偏移会翻转低位字段；(iv) 继续"更多块落在房子上"（矩形图幅）——已饱和（D4-17）；(v) 把精度当内容——违反约束 2。
- **最重要的提醒**：64×8 bit 对 8+ 室在无损意义上已不够（794 > 512），任何表示改动在该层的天花板约 .88–.90、整体约 .92–.93；"+3 pp"是拉伸目标，+1.5–2 pp 是现实目标。发射前先做两件零成本的事：HouseExpo 面板的 exact vs 1-px 容差 F1（量"存在误差"占多少；v293 上两者差 5 pp，D3-3）和 v384 的码级扰动测试（决定 B 是否有余量）。
