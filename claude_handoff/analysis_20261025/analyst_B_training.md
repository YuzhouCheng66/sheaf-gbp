## 2. 预算算术

| rate (s/upd) | 一个 lease 最多可训（链规则） | 16k 用时 | 3× (48k) 两种子 | 6× (96k) 两种子 |
|---|---|---|---|---|
| .10（16×16×1 布局） | **55,500** | 1,786 s | 2 lease（各 1 个 48k 单余弦） | 4 lease |
| .12（W1，8×8×4） | **46,000** | 2,106 s | 2 lease（46k ≈ 2.9×） | 4 lease（2 × 46k 周期） |
| .20–.22（W2） | **25,000–27,500** | 3,400–3,700 s | **4 lease**（2 周期 × 24–25k） | 8 lease（4 周期） |

实测全程 s/upd（含 val）：A .127–.130，W .207–.208；3S-A 完成 2,100 s，3S-W 3,383–3,395 s。

- **周期 vs 一个长余弦**：W = 1 可以在一个 lease 里跑 46k 单余弦——比 3 个 16k 热启动周期便宜 3 倍、且优化上更好（2D 的热启动周期把峰值降到 1e-4，LR 积分只有第一周期的 1/3，仍各得 +2.4 / +1.0 pp）。W = 2 一个 lease 装不下 48k，只能走 2D 批次 R/S/W/X 的热启动周期（`--init-from` 加载权重，Adam 与日程重开，每周期一个 lease）。
- **更大的峰值 lr**：梯度范数日志里最大 2.3（W2 upd150），裁剪 5 从未触发，有余量；在 1.2 节的漂移受限区，lr × 2 近似等于 LR 积分 × 2。但 lr 的最优值从未在 3D 测过，退火质量也会变，它是一个独立变量，列第 6 位。
- **warmup**：200 步 = 1.25 %，无关紧要，不动。
- **常数后衰减（WSD）**：余弦到 5 % 的 LR 积分 = .525·T·lr；"75 % 常数 + 25 % 线性到 5 %" = .88·T·lr，**同样更新数下 LR 积分 ×1.68**。在漂移受限区这相当于白送 1.7× 的训练长度；风险是退火段短，而退火段恰恰给了 K0 可变结构 +2 pp 的阈值效应。列第 4 位，不先做。
- **更多场景 / 更新（梯度累积 vs 真 batch）**：真 batch 不可行——`CHART_M` 是全局（:409）、每景森林不同、公共平面随 L 变；只能累积。累积在等 GPU 时间下把更新数减半；1.2 节表明 W2 的进展 ∝ ∫lr 而非受噪声限制（lr 降 10× 时损失没有"额外"下降），所以累积预期 **≤ 0**。而且每次更新已经是 40 个解码样本（8 agent × 5 hop）。不做。
- **数据轮数**：46k 更新 = 9.8 轮 4,708 景（现在 3.4 轮，TRAIN−VAL 差 +1.6 ~ +2.8 pp）。若长训后差距涨到 > 5 pp，再扩缓存——生成 4,708 景用了 4,392 s CPU，14,400 景约 3.7 h CPU，不占 GPU。

读法：
- **"楼板吃掉梯度"不成立。** 楼板占权重 19 % 但梯度 0.1–0.2 %，BCE 已经把它学到饱和（忽略 known 头时召回 1.000），再加也好不了、去掉也省不出梯度。类平衡 / 去楼板加权预期效应 **0**。距离变换目标也不会从这里获益。
- **梯度真正去哪了**：一半在 free（其中 1/3 是贴着表面的边界抖动），**三成在家具**（权重份额只有 7–9 %，但每单位权重的损失 ≈ 1.0 = 基本在猜），内墙 6–15 %，边界墙 11–13 %。内墙的每体素损失最高（K0 时 p(占据) ≈ e^−1.44 ≈ .24），但它在 K0 目标里只有 0.3 % 的体素、1.1 % 的权重；按 hop 权重合计，内墙在总梯度里约 9 %。**内墙的梯度确实小，但原因是它在 K0 目标里几乎不存在（内墙占 K0 墙体素 4–6 %，R8 占 26–29 %），而 K0 拿了一半权重**——这是第 3.5 节的 hop 权重问题，不是类权重问题。
- **要不要把家具降权来救墙？** 家具吃 3 成梯度而召回只有 .23–.25；但家具区 F1 是用户判据的一部分、也是 var F1 的一部分，而且 TRAIN 缓存里没有家具掩码（`train` 只存 private / reached / edges / chart_m，:354-356），按真值类别加权要重建缓存。不列为候选。

### 3.3 known 头的否决：目标函数里最大的单一漏点

`predict`（:252）：known_logit < 0 → 输出 unknown，不管 occ_logit。指标在目标已知范围内算，被判 unknown 的目标占据体素全是 FN。

- 被否决的目标已知占据体素比例：**A1 21.1 %（K0）/ 14.1 %（R8）；W1 16.7 % / 13.1 %**。按类（W1 K0，有否决 → 无）：楼板 .915 → 1.000，边界墙 .684 → .927，内墙 .262 → .296，家具 .227 → .394；R8：楼板 .934 → 1.000，边界墙 .655 → .890，家具 .252 → .385。
- 机理：首击表面就是已知区的边界——表面体素是"已知"的最后一层，下一体素就是 unknown。known 头要把 known/unknown 的分界精确放在表面体素的外侧，而 known-BCE 对 524k 体素等权（:242），87 % 是 unknown、87 % 的已知是内部 free，边界层只有一体素厚、没有任何加权。它学会了画大片的 known 团块，分界线抖 ±1 体素；抖进来一体素，整条墙面就丢。占据头在表面有权重 5，所以占据头在边界墙上其实已经到 .93。known 头的损失有 51–60 % 来自 unknown 一侧（把 unknown 判 known = FPR），说明分界是双向抖动，不是单向偏置；**双侧加权能同时压 FN 和 FPR**。
- 决策规则扫描（同一检查点，不重训，6 景）量出这条杠杆的上限与代价：

| 规则（W1） | K0 表面 / 可变 / FPR | R8 表面 / 可变 / FPR | 占据精度 K0 |
|---|---|---|---|
| 基线 known ≥ 0 | .736 / .531 / .017 | .672 / .480 / .045 | .775 |
| known ≥ −1 | .764 / .586 / .028 | .689 / .515 / .070 | .747 |
| occ ≥ 1 且 known ≥ −3 → 占据 | **.790** / .621 / .032 | .709 / .540 / .088 | .777 |
| **真值 known 掩码（known 头理想化上限）** | **.781 / .624 / .000** | **.704 / .549 / .000** | .732 |
| occ ≥ 0 不看 known | .781 / .624 / **.924** | .704 / .549 / .900 | — |

A1：真值 known 掩码 K0 .696 → .756（+6.0）、可变 .450 → .583（+13.3）；R8 .649 → .688（+3.9）、可变 .408 → .506（+9.8）。

读法：(i) **只修 known 头、占据头不动**，R8 表面 +3.2 / +3.9 pp、可变 +6.9 / +9.8 pp 是上限；(ii) 事后挪阈值能拿到一半，但 FPR 要付 1–4 pp（R8 FPR 本来就 .036–.042 > .03 的保护线）；(iii) 占据头在 unknown 区完全没被训练（规则"不看 known"FPR .92），所以不能靠占据头越权，**必须在训练里把 known 头的分界磨尖**。
- **提议的单变量**（`stage_loss` 一行）：known-BCE 的权重改为 `1 + 4 × [边界体素]`，边界体素 = 目标表面体素（已知侧）∪ 与已知体素 6 邻接的 unknown 体素（未知侧），并改为加权平均。与占据项的表面权重镜像、双侧对称、不依赖缓存里没有的掩码（全部由 target 推出，`surface_of` / `dilate6` 已有，:225-236）。机制读数：被否决比例 .131 → ≤ .08（R8）。2D 线用同样的否决规则（`train_v378.py:400-403`）但 K0 到了 .939——2D 的边界是 2D 团块里的 1 px 线，分界容易；3D 多了一个方向的抖动。此处未经检验，所以才要测。

### 3.4 距离变换（DT）头：2D 最终配方用的其实不是 BCE

- 2D 工作基线 `train_v378.py` 的损失是 **known-BCE + 截断 DT 的 L1 回归**（`:375-397`，`weight = known × (1 + 4·[DT ≤ 1.5])`，`wall := softplus(ch) < .5`，`:16` 的 docstring 写明）。3D 系列（v400 → v420）换成了表面加权 BCE，**从未做过配对比较**。
- 2D 证据：第一夜的解码器族上界（报告 §2 D3）cnn_bce R8 .805 vs cnn_dt **.865**（+6 pp）；DT 头随后留在最简架构里（N2-4）。反面：DT-L1 在门洞位置回归中位数会把门填上（§D3-3："DT 头倾向画连续墙、封住门洞"，门洞召回 .28–.31），SDF 变体（v343）无增益，256 分辨率有"1 px 悬崖"。
- 3D 实现上：DT 要各向异性（竖向 0.1 m、水平 6–16 cm，`owned_ceiling_v370.py` 的 `truncated_dt` 是 2D 的），截断半径与权重带要重定，known 头的否决问题照样存在。预期：对墙的"存在性"有利（2D +6 pp 的上界证据），对家具（薄腿、悬挑）不一定。它是一个合法单变量，但机制证据不如 3.3 直接，列第 5 位。

### 3.5 hop 权重 .5 / .125 × 4

- 每个 hop 的损失先按体素归一（:242, :245），所以 R8 目标虽大 2.6×，它的梯度量级和 K0 一样；权重 .125 让部署指标 R8 只拿 **1/8** 的损失，K0 拿一半。内墙在 K0 目标里只占墙的 4–6 %，在 R8 里 26–29 %——**权重配置本身把"只有码的内容能传过去的东西"放在了最轻的那一项上**。
- 1.3 节：训练过程里 k8 − k0 的占据损失差单调扩大，VAL 融合差从 −1 扩到 −5 / −8，退火段 R1…R8 单调下降而 K0 上升——与"模型在低 LR 段向 .5 权重的 K0 项收敛"一致。2D 用同样的权重，但 2D 的融合是无损的（D4-10 ≤ .4 pp），所以 2D 从 e1 的 −9 pp 收到最后的 −2.4 pp；3D 的融合有损（第 4 节），权重问题才显现。
- 单变量：`WEIGHTS = {0: .25, 1: .0625, 2: .0625, 4: .125, 8: .5}`（R8 一半，K0 四分之一，总和不变）。预期 R8 表面 +1–3 pp、K0 −1–2 pp；机制读数：融合 R8 与"并集直编"R8 的差从 5.6 pp 收窄 ≥ 2 pp。2D 试过的两个目标侧融合修正不应重做：一致性损失（v345 单次 +4.6 后 v346 双种子配对 +0.9 / 0.0，未采用）、覆盖率精度 q = 4 × 覆盖（v345 −4.7 pp）。

## 4. 融合差 R8 − K0 = −7 pp：训练信号还是表示？

### 4.1 "理想同态"诊断（2D D4-10 的 3D 版，首次）

对每个 agent，把它的 R8 并集目标图当成"自己的观测"送进同一编码器，得到并集的码，再按 K0 方式解码（无 join）。三者在同一面板（6 景，VAL 每层 index 2–3）：

| 检查点 | K0（自码 → 自图） | R8 融合（join → 并集） | **R8 并集直编（oracle）** | 融合损失 = oracle − 融合 | 目标难度 = K0 − oracle |
|---|---|---|---|---|---|
| A1 表面 | .691 | .634 | .677 | **4.3 pp** | 1.4 pp |
| A1 可变 | .404 | .363 | .415 | **5.2 pp** | −1.1 pp |
| W1 表面 | .737 | .673 | .729 | **5.6 pp** | 0.8 pp |
| W1 可变 | .509 | .452 | .531 | **7.9 pp** | −2.2 pp |
| W1 家具区 | .233 | .248 | .302 | 5.4 pp | — |
| W1 内墙召回 | .286 | **.333** | .310 | −2.3（融合更好） | — |
| W1 边界墙召回 | .643 | .625 | .718 | **9.3 pp** | — |
| W1 FPR | .018 | .0275 | .0277 | 0 | — |

证据块比例：自码 .31，并集码 .58（两者在 R8 上给解码器的覆盖掩码是同一个集合，所以差异不在掩码而在每块的码值）。

读法：
- **差距的 75–85 % 是融合损失**；并集目标本身并不更难（可变结构上并集直编甚至比 K0 高）。3D 的 max join 把 4–6 pp 丢在了马赛克里，2D 是 ≤ .4 pp。
- 丢的**不是内墙**（融合 ≥ 直编：两个 agent 各看墙的一面，任一面的码都能放对墙）而是**边界墙和家具**：一个块被两个 agent 各看到一半（互补半块），max 只留一半的码，解码器只画一半——2D N2-5 判定为表示问题（"1 个标量/块无法同时表达两种互补半块视图的并集"）。3D 的块（16×16×8 体素）内容多得多，问题放大 10 倍是合理的。

### 4.2 训练信号侧有什么可做

- `select`（:179-183）用 `argmax` 选源再 `gather`：梯度只流向赢家的 (p, η)；线路量化是恒等 STE（`train_v378.py:140`）。**"谁该赢"没有任何梯度**——输家永远得不到"你该让位"的信号，赢家也得不到"你赢错了"的信号。q 的语义完全是涌现的：A1 的 q 跟块内**占据量**（Spearman .68，跟覆盖率只有 .26），W1 的 q 跟**覆盖率**（.78；2D N2-0 是 .91）；多源块（6 景 856 块）里 max-q 源 = max-coverage 源只有 **65–67 %**。两个只差解码器宽度的运行学出两种 q 语义，说明精度头的训练信号弱而不定——但 4.1 表明即使选对了源，互补半块仍然丢一半，所以修选择规则的上限有限。
- 训练侧能动的只有权重（3.5 节的 hop 重配）。2D 已否定的一致性损失和覆盖率精度不重做。
- **分离训练信号与表示的单变量测试**：
  1. 零成本、已排队：3S-L 的 R8 上限（自由码只拟合自身观测 + 部署 join）。若自由码的 R8 ≈ K0 − 1 pp，表示装得下、差距在编码器 / 训练；若自由码 R8 也比 K0 低 ≥ 4 pp，是表示（互补半块），训练侧改不动。
  2. 一个 GPU 批次：hop 重配（3.5 节），机制读数用 4.1 的 oracle 差——只有"融合 R8 − 直编 R8"收窄才算训练信号在起作用；若 R8 涨而差不收窄，那是 R8 权重让解码器学得更好地渲染并集（也有用，但归因不同）。
  3. 零成本、未跑：把 join 的选择换成按块已知体素数（oracle selection），解码器不动，看 R8 变化——量出"选错源"那一部分的大小。

### 5.1 第一个要跑的：#1 known-BCE 边界加权

- **为什么先于训练长度**：(a) 它有**测量过的上限**（真值 known 掩码：R8 表面 +3.2 / +3.9，可变 +6.9 / +9.8）和清楚的机制（被否决比例 .131 / .141），不依赖外推；(b) 最便宜（2 lease，与 3S-W 完全配对，16k 相同）；(c) 它修的是目标函数，增益不会像"学得快"那样被更长训练吸收（A1→W1 的否决比例 .211 → .167 说明容量帮了一点，但 .167 远不是 0）；(d) 先定下正确的目标再花 4 个 lease 长训，比反过来省。
- **实现**：`train_3d_v422.py`（或 v424）`stage_loss` 内，`known_bce` 改为加权平均，`w_k = 1 + 4·(surface_of(target) | (dilate6(known) & ~known)).float()`；其余逐位不变。`test_3d_v422` 加一条：权重为 0 时与 v422 逐位一致。
- **对照**：`runs/v422-decoder/a-s<seed>`（W = 2、16k、同种子 → 编码器 / head / 解码器初始张量相同，数据顺序相同）。
- **预注册判据（final VAL 24 景，按种子配对，Δ = 新臂 − 3S-W）**：两种子 Δ R8 可变 ≥ +3 pp 且 Δ R8 表面 ≥ +1.5 pp 且 R8 FPR ≤ 3S-W + 0.3 pp → **known 头是杠杆**；两种子 Δ R8 表面 < +1 且 Δ R8 可变 < +2 → 不是；其余 ambiguous。机制读数（只报告）：被 known 头否决的目标已知占据体素比例（K0 / R8）应从 .167 / .131 降到 ≤ .08；若指标涨但这个比例不降，增益不能归到此机制。附报 Δ K0、家具区、容差 1、fresh、3S-A 绝对判据、融合差。
- **风险与混杂**：(i) 加权让 known 头更"外扩"而抬高 FPR——双侧对称权重是为此设计的，FPR 保护写进判据；(ii) 被否决的体素里有一部分占据头本来也会判错（表 3.3 "无否决"列是占据头的真实召回 .93 / .39，所以边界墙能回收、家具回收有限）；(iii) 6 景诊断外推到 24 景面板有 ±1 pp 的面板差。
- **什么会证明我错**：两种子 Δ R8 表面 < +1 pp 而否决比例确实降到 ≤ .08——说明被 known 头挡住的体素换成了占据头的错误（占据头在边界并不像表 3.3 那样可靠）；或者 FPR 升 > 1 pp——说明 known 边界不是"抖"而是"信息不足"，加权只是把分界推出去。

### 5.2 第二个：#2 训练长度（W2 两周期），在 #1 的胜者上

- 第 1 周期 25k（峰值 3e-4，新 lease）、第 2 周期热启动 25k（峰值 1e-4，`--init-from` 只加载权重，Adam 与日程重开，与 2D 批次 R/S/W/X 一致）。合计 50k ≈ 3.1×。
- **判据**：两种子最终 Δ R8 表面 ≥ +3 pp（2D 用 +1；这里余量大、噪声 SE .5–.8，用 +3 避免把融合差扩大的运行误判为成功）且 FPR ≤ +0.3 → 训练长度是杠杆；第 1 周期结束时的次级比较 Δ ≥ +2 作为早停信号（若第 1 周期 25k 两种子都 < +1，第 2 周期不跑，判"W2 已被容量 / 表示限制"）。附报每 1/4 的 R8 − K0 差：若差继续扩大 ≥ 2 pp，下一批必须是 #3。
- **什么会证明我错**：25k 单周期两种子 Δ R8 < +1.5 pp 且 K0 可变 < +4 pp——1.2 节的"LR 地板"读法就错了，W2 其实也在饱和，剩下的全是表示（3S-L 会给出上限）。

### 5.3 第三个：#3 hop 权重重配

只有在 #2 的 R8 − K0 差仍 ≥ 7 pp 或继续扩大时才值得花 2 个 lease；判据：两种子 Δ R8 可变 ≥ +2、表面 ≥ +1、K0 表面 下降 ≤ 2 pp、FPR ≤ +0.3；机制读数：融合 R8 − 并集直编 R8（4.1 的脚本）收窄 ≥ 2 pp。
